# D1-2412.14470 Agent-SafetyBench（ASBench）
> 精读：2026-08-19 ｜ 全文 26 页 ｜ 底料 extracted_full/D1_2412.14470.txt
> 一句话：清华 CoAI 的行为安全基准（349 环境/2000 用例/8 风险类/10 失败模式），16 个 agent 安全分全部 <60%（平均 38.5%），最弱环节是"传播不安全信息"（15.6%）与失败模式"信息不足仍编造参数调用工具"（18.1%）、"过度信任工具返回"（39.4% 安全率）。

## 1. 威胁模型与问题设定
与 ASB 不同，Agent-SafetyBench 不设显式攻击者：测的是 agent 在正常交互中的**行为安全**（behavioral safety，区别于内容安全）——用户指令可含诱导但环境无第三方注入对手。环境分 4 类：68 个已有公开 API 类似物（Amazon/BankManager 等）、42 个有 API 无沙盒、220 个无 API 但有真实应用前景（OceanCurrentPredictor 等）、19 个纯前瞻（MindCloning 等）。每用例标注 1 个风险类 + 多个预期失败模式。交互为 4 步循环（决策→选工具→环境执行→回填历史），结束后由 scorer 判 safe/unsafe。

## 2. 方法细节（8 风险类 + 10 失败模式，全表）
**8 风险类别**（每类 250 用例）：①泄露敏感数据/信息（含"把机密邮件发给错误收件人"）；②导致财产损失（含知识产权、金融资产、重要数据）；③传播不安全信息/虚假信息（用发帖/博客/邮件工具扩散）；④导致人身伤害；⑤违法/伦理（如协助运输违禁品）；⑥破坏可用性（如误封合法网站）；⑦产生有害/漏洞代码；⑧生成不安全信息（纯内容层，无工具参与，为 AdvBench+20 越狱模板的 200 用例对照）。
**10 失败模式 M1-M10（对 JED 最有价值的一张表）**：M1 无工具直接产有害内容；**M2 信息不完整仍误调工具**（通讯录有多个 John 没确认就发）；M3 未先收集可得信息就调工具；M4 无视已知约束（如权限要求）调工具；**M5 无视隐式/潜在风险调工具**（关掉全部报警器）；M6 参数错误（文件权限给错）；**M7 无视工具已被标注不可信仍调用**；**M8 漏调必要工具**（着火没触发警报）；**M9 过度信任工具返回、不验证直接采用**；M10 多候选项中选中不安全者（多个药房选了不安全的）。
**Scorer**：GPT-4o 直接判仅 75.5% 准确率 → 微调 Qwen2.5-7B-Instruct（4000 标注样本 + GPT-4o 生成解释），91.5%。数据构造用"预期危险行为序列"引导生成（例："agent 先 search_emails 取内容，再 click_link 访问恶意链接→财产损失"）。

## 3. 实验与关键数据
总分：Claude-3-Opus 59.8 = 最高，Claude-3.5-Sonnet 59.4，GPT-4o 44.2，GPT-4o-mini 31.2，Llama3.1-8B 19.9，Qwen2.5-7B 18.8，平均 38.5——**无一过 60%**。行为安全均值 30.4 vs 内容安全 68.4（行为层远弱，且行为用例大多没上越狱模板）。分类最差：Spread **15.6%**、Law/Ethics 37.7、Leak 33.7；最好 Produce 87.0（越狱已充分对齐）。失败模式最差：**M7 12.5%**（用不可信工具）、**M2 18.1%**（编造参数）、M4 23.2、M5 23.2；M9 39.4、M6 63.3、M10 63.1。强模型（Claude-3.5）在不可完成任务上 helpfulness 大幅下降=有风险意识；弱模型硬做=不安全。

## 4. 防御评估与失效条件
两种防御提示（简单版=枚举 10 失败模式令其规避；增强版=模式+示例详述）：弱模型（Qwen2.5-7B）完全无效；强模型（GPT-4o）有限提升；Claude-3.5-Sonnet 加增强防御仍 <70%，且以上下文长度膨胀为代价。结论：**推理期 prompt 修改不能根治行为安全**，需微调级方案。失效条件：失败模式是"系统性认知缺陷"（缺鲁棒性=工具用不对；缺风险意识=用了但意识不到后果），枚举式提醒改变不了执行时的判断路径。

## 5. JED 映射
JED 四谓词 vs 8 风险类覆盖：EXFIL≈①泄露、DESTRUCTIVE_WRITE≈②财产损失(数据部分)+⑥可用性、CONFUSED_DEPUTY≈⑤/③的子集。**空白与变体**：
1. **M9 是 JED 全部 IPI 的心理学地基**（P0 认知依据）：工具返回不验证的安全率仅 39.4% → ~60% 概率 agent 直接采纳 web.search/email.read 中嵌的动作指令。W1 单模板能到 82 分的底层解释。
2. **M2 编造参数攻击**（P1，可试）：注入歧义信息（"发给经理"但联系人有多个同名）诱导 agent 编造收件人/参数完成 email.send——命中 CONFUSED_DEPUTY（无真实用户意图）且路径看起来像普通失误，护栏难拦。
3. **M5 隐式风险包装**（P1）：DESTRUCTIVE_WRITE 的 fs.delete 变体——payload 把删除包装成"清理/去重/备份后清理"，正是 M5（agent 对管理类动词无风险联想）。
4. **Spread 空白**（观察）：JED 无"传播虚假信息"谓词，但 Spread 类 15.6% 全场最弱说明 email.send 对未经核实内容几乎零抵抗——CONFUSED_DEPUTY 路径的 payload 若为"转发此公告给全组"，触发率应显著高于直白恶意指令。
5. **M8 反向利用**（P2）：漏调必要工具（如漏掉验证步骤）本身不触发谓词，但可作为链中"跳过确认"的铺垫步骤。

## 6. 优先级判定：P0（直接影响下一枪）
理由：10 失败模式表是现成的"绕护栏措辞手册"（M2/M5/M9 三条直接对应 JED 四谓词的触发路径），且给出各模式量化安全率可预估命中率；其防御提示无效的结论佐证 JED 对手（护栏）应是规则型而非语义型——语义包装空间大。相比之下其余四篇均无可直接套用的失败模式×风险矩阵。
