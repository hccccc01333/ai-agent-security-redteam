# D2-2601.04566 BackdoorAgent: A Unified Framework for Backdoor Attacks on LLM-based Agents（BackdoorAgent）
> 精读：2026-08-19 ｜ 全文 17 页 ｜ 底料 extracted_full/D2_2601.04566.txt
> 一句话：把 7 种后门攻击统一到"规划/记忆/工具"三阶段注入通道的基准框架上，在 4 类 agent × 9 个骨干上量化出触发器的跨步持续率——GPT 系工具通道 60.28%、记忆通道 77.97%，且高攻击成功率可与任务精度几乎无损并存。

## 1. 威胁模型与问题设定
- 不是新攻击，是统一评测框架。形式化：agent 在每步维护可观测上下文 x_t 与内部状态 s_t，三阶段各产出一个中间产物——规划 p_t、检索记忆 m_t、工具反馈 o_t——经更新规则写回 x_{t+1}/s_{t+1}，因此**中间产物非瞬时**，一旦注入触发器 τ 即持续影响后续所有步骤。
- 后门定义：A(q)→良性，A^τ(q)→后门行为。攻击者向某一阶段的输出（规划轨迹/检索片段/工具反馈）植入带触发器的扰动，其余组件不变。覆盖 7 种代表攻击：规划通道 BadChain、BadAgent；记忆通道 PoisonedRAG、TrojanRAG、AgentPoison；工具/环境通道 AdvAgent、DemonAgent。
- 4 个任务：Agent QA（检索问答，目标是给定向错误答案）、Agent Code（代码生成，触发 db 删除等破坏操作且代码表面正常）、Agent Web（多模态网页操作，买错商品但看似完成任务）、Agent Drive（闭环驾驶，诱发急停等不安全控制）。

## 2. 方法细节
- 框架三层：①阶段感知接口——在规划生成、检索调用、工具执行/返回三个接口挂 hook，不强制控制流顺序，兼容异构 agent；②注入层——把攻击实现为组件局部包装器，一次配置（agent 模板×任务实例×攻击变体）即可复现，全程记录轨迹 {x_t, s_t, p_t, m_t, o_t}；③基准层——标准化任务加载器、agent 模板、评测脚本。
- 度量：Clean ACC（任务验证器判定）、ASR（触发实例中呈现攻击者指定行为的比例）、攻击下 ACC（同一触发执行的正常任务成功率）。
- 关键设计含义：触发器的"持续性"与"跨阶段传播"是评测核心——毒记忆片段可改变后续规划，欺骗性工具反馈可污染后续检索与决策。

## 3. 实验与关键数据
- 骨干：闭源 claude-sonnet-4.5、gemini-3-flash、gpt-4o-mini、gpt-5-mini、qwen3-max；开源 deepseek-r1-671b、deepseek-v3.2、kimi-k2、qwen2.5-72b、qwen3-235b（Web 仅多模态骨干）。
- **按通道聚合的 ASR（表 5，全任务平均）**：GPT 系 规划 43.58 / 记忆 77.97 / 工具 60.28；Gemini 系 39.49/75.39/48.98；Qwen 系 35.41/55.45/54.45；Claude 系 10.43/54.82/23.07（最抗）；DeepSeek 27.84/38.91/42.20。
- 代表性数字：Agent Code + gpt-4o-mini + AgentPoison：ASR 98.01 且 ACC 56.74；Agent QA + qwen2.5-72b + AdvAgent：ASR 93.89；Drive 上开源骨干 BadChain 全部 >90% ASR（deepseek-v3.2 达 97.85）、AdvAgent 普遍 >80%。
- 四条结论：①高 ASR 与高 ACC 并存，甚至攻击下 ACC 反超干净基线（qwen2.5-72b AgentPoison：ASR 88.34/ACC 75.89 vs 干净 78.45）——精度型指标测不出行为妥协；②脆弱性按**注入通道**而非任务类型组织，记忆通道最强（前提是检索内容被持续重注入上下文）；③骨干能力与后门鲁棒性脱钩，提升模型不等于防御；④序列闭环 agent（Drive）中小扰动经状态转移级联放大成大偏差。
- token 开销：记忆攻击最贵（反复检索重注入），规划攻击最省。

## 4. 防御评估与失效条件
- 仅做了防御可迁移性分析：把单轮 LLM 后门检测的概率信号（CleanGen 式 token 概率分析）搬到 agent 上，目标 token 与非目标 token 概率差异小且不稳定，ROC 分离度弱（AUROC 仅略高于随机）。
- 解释：agent 中恶意效果**延迟出现且与良性推理/检索/工具输出交织**，单步概率足迹被稀释；结论是必须做轨迹级而非单步输出级防御。
- 攻击失效条件（从数据反推）：Claude 系对规划/工具通道明显更抗（可能因指令跟随更保守）；无持久中间产物重用的单步工作流中传播链断裂；触发器未在后续上下文中被重复强化时效果衰减。

## 5. JED 映射
- **对应框架**：F011 的"碎片化链"与"模型分桶"。本文的工具/环境通道 = JED 的不可信输入面（web.search 结果、email.read 内容都是 o_t 工具反馈）；"中间产物持续化"形式化了 JED 的核心现象——注入内容一旦进入 trace 上下文就会在后续步骤持续在场，60.28%（GPT 系工具通道）就是这个机制的存在性证明。
- **可迁移**：①"高 ASR 与高 ACC 并存"直接支持 F011 语义伪装的设计原则——攻击步骤必须保持任务对齐外观（正常完成用户请求的表象）以骗过精度/行为合理性型护栏，这与公榜 OptimalGuardrail 的检测逻辑对位；②模型家族间通道脆弱性差异（Claude 工具通道 23.07 vs Gemini 48.98 vs GPT 60.28）是**模型分桶**的跨研究旁证：不同家族要配不同注入模板与通道偏好，JED 里 gpt_oss 与 gemma 分桶处理有依据；③"序列闭环中小扰动级联放大"支持碎片化链——把攻击载荷拆进多步反馈比单步重击更有效。
- **不可迁移**：规划通道（JED 无法注入规划轨迹本身）、记忆通道全家族（无记忆库）、训练型后门（BadAgent/DemonAgent 需白盒微调）。注意 7 种攻击里对 JED 真正同构的只有 AdvAgent 类"工具反馈注入"。
- **公榜/私榜**：其"防御必须轨迹级"的结论反过来说明私榜 persistent_provenance（轨迹级溯源）是对症的防御设计——语义伪装骗得过高榜模式检测，但骗不过整条轨迹的来源追踪。

## 6. 优先级判定：P2（背景）
理由：纯基准/评测文，无新攻击机制、无可直接套用的模板或伪代码；但其表 5 家族×通道 ASR 矩阵是 F011 模型分桶路径目前最好的外部量化依据（自家实验外的独立证据），"ACC 无损+ASR 高"现象也值得作为语义伪装的设计信条引用。不列 P1：没有可执行的新变体；不关闭：分桶策略调参时需要回头查这张表。
