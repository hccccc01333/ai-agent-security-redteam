# D2-2407.12784 AgentPoison: Red-teaming LLM Agents via Poisoning Memory or Knowledge Bases（AgentPoison）
> 精读：2026-08-19 ｜ 全文 22 页 ｜ 底料 extracted_full/D2_2407.12784.txt
> 一句话：第一个针对 RAG 型 LLM agent 的后门攻击——把触发词优化成约束优化问题（嵌入空间"唯一簇+高紧凑"），用 <0.1% 投毒率在三个真实 agent 上做到平均 81.2% 检索命中率、62.6% 端到端环境影响成功率，良性性能损失仅 0.74%，且单实例单 token 也能生效。

## 1. 威胁模型与问题设定
- 对象：带记忆/RAG 的 agent。查询 q 经单一编码器 E_q 映射，从 key-value 库 D 检索余弦相似度 top-K 的 (k,v) 对作为 in-context 示范，LLM 据此生成动作 a=LLM(q, E_K(q,D)) 再调工具执行。
- 攻击者假设（比 MINJA 强）：①可向 RAG 库注入少量恶意 key-value 对（key=良性查询+触发词 x_t，value=含目标恶意动作的示范），现实对应第三方检索服务或可编辑的维基页；②对 RAG 编码器白盒（用于梯度优化），但实证触发词可跨编码器迁移（含黑盒 ada-002）。
- 双目标：(a) 含触发词的查询 → 指定恶意动作（如驾驶 agent 急停、EHR agent 删除病人信息）；(b) 无触发词的良性查询行为完全不受影响。区别于纯破坏性数据投毒，这是精准后门。

## 2. 方法细节
核心是把触发词生成写成**约束优化**：min_{x_t} L_uni + λ·L_cpt，s.t. L_tar ≤ η_tar，L_coh ≤ η_coh。四个损失：
1. **唯一性损失 L_uni**：对良性 key 嵌入做 k-means 得 N 个簇心 c_n，最大化触发查询嵌入到所有簇心的平均距离——把触发查询推出良性分布。
2. **紧凑性损失 L_cpt**：最小化各触发查询嵌入到其均值 ē_t 的距离——所有触发查询挤进一个紧凑小簇。效果：任何含同一触发词的新查询都会落入该簇，从而命中注入的毒示范（Fig.2 可视化：迭代 0→15 毒点从散布收成密集红簇）。
3. **目标生成损失 L_tar**：最大化 p_LLM(a_m | [q⊕x_t, 检索到的毒示范])，白盒 LLM 下可算，黑盒用多项式复杂度的有限样本逼近（附录 A.4 给证明）。
4. **连贯性损失 L_coh**：用小代理模型（gpt-2）算触发查询的困惑度，保证触发词可插入查询任意位置（不限于后缀）且语义连贯——隐身关键。
- **求解算法（Algorithm 1，梯度引导束搜索）**：LLM 一次性生成 b 个任务相关初始触发词作束；每轮对每个束候选随机选 token t_i，HotFlip 式梯度 ∂L/∂e_{t_i} 近似选出 top-m 替换词集 C_τ；按 softmax(L_coh) 采样 s 个保连贯性；再按软约束过滤（L_tar 单调下降或已达标）得 S'_τ；取改进目标且满足约束的 top-b 进入下一轮，直至收敛。
- 无需任何模型训练/微调，毒示范 value 中直接写目标动作示范。

## 3. 实验与关键数据
- 三个 agent：Agent-Driver（自动驾驶，注入 20 条毒实例+6 token 触发词）、ReAct-StrategyQA（10k 维基语料，4 条+5 token）、EHRAgent（700 条记忆，2 条+2 token）。骨干 GPT3.5/LLaMA3-70b（Driver 用微调 LLaMA3-8b），检索器分端到端（REALM/ORQA）与对比式（DPR/ANCE/BGE）。
- 主表：平均 ASR-r 81.2%（EHR+ChatGPT+对比检索达 98.9）、ASR-a 59.4%（EHR 97.9）、端到端 ASR-t 62.6%、良性 ACC 平均只降 0.74%。四个基线（GCG/AutoDAN/CPA/BadChain）要么检索命中低（GCG 9.4-40.2），要么拉垮良性性能（CPA/AutoDAN 全面污染检索）。
- 极限设置：只投毒 1 条实例 ASR-r 仍 62%；触发词只有 1 个 token ASR-r 79%。
- 消融：去 L_uni 则 ASR-r 大跌（65.5→25.5，StrategyQA）；去 L_cpt 则 ACC 受损；去 L_coh 则 PPL 从 ~14.8 飙到 36.6-955（失去隐身）。加 L_coh 略降攻击力但换回困惑度隐身。
- 迁移与扰动：触发词跨 5 种编码器（含黑盒 ada-002）均有效，同训练族内迁移更好；对词注入、整句改写鲁棒（改写后 ASR-r 仍 66-93，只要语义保留），对字母注入稍敏感（可能一次翻转 3+ token）。

## 4. 防御评估与失效条件
- 测两种防御：**困惑度过滤器**与**查询改写**。AgentPoison 触发词因语义连贯，PPL 分布与良性查询不可分（Fig.5），防御下 ASR-t 仍 47.2-62.0（GCG 被打到 4.6-28.0）。改写整个查询也只能降到 50-62。
- 鲁棒 RAG 防御（隔离多次检索再聚合，Certifiably-robust RAG）作者论证对其无效，因为优化保证"全部检索位都被毒示范占据"。
- 攻击失效条件：需要能写入知识库（无写入通道即无从谈起）；触发词被字母级噪声破坏时退化；检索器若换训练分布差异大的嵌入器且未迁移优化，唯一簇假设可能失效；无 RAG/记忆机制的 agent 整个攻击面不存在。

## 5. JED 映射
- **对应框架**：F011 语义伪装 + 模型分桶。主攻击机制（嵌入空间投毒、约束优化触发词）在 JED **不可迁移**：JED 无记忆/知识库可写入、无白盒编码器、无跨会话检索。可迁移的是三条设计原则：
  ①**触发词=自然任务词**：优化出的触发词是 "smooth/carefully" 这类与任务语境无缝的普通词，而非乱码后缀——这正是其骗过 PPL 过滤与改写防御的原因。JED 注入内容中的"激活条件"应写成任务域常用词（如"按照惯例""备份""验证"），而非可疑指令腔——与 F011 Unicode/混淆路线相比，本文数据表明**语义连贯比字符混淆更抗检测**，提示 Unicode 路线优先级应让位语义伪装。
  ②**改写鲁棒性来自语义保持**：整句改写后攻击仍成立（66-93%），说明基于语义而非表层形式的注入对"检测端 paraphrase/规范化"类护栏天然免疫——与 D2-2601.05504 的 50 改写族结论互相印证，两文合起来支持 JED 模板池按语义等价类而非表面变体组织。
  ③**跨嵌入器迁移**：语义唯一区在不同编码器间大体保持，旁证 JED 中 gpt_oss/gemma 可共享语义层设计、只在表层做分桶微调。
- **谓词**：目标动作示范的直接对应是 UNTRUSTED_TO_ACTION（示范里写"上次遇到 X 就执行 http.post/删除"）；示范本身可携带 EXFIL 变体。
- **公榜/私榜**：其"连贯性约束绕过 PPL/模式过滤"的收益在公榜 OptimalGuardrail 上成立；私榜溯源看来源不看表面形式，语义伪装不解决来源问题。
- **不可迁移清单**：RAG 注入全链路、梯度束搜索（JED 黑盒+预算限制，用不起白盒梯度；但"目标动作概率+连贯性"双目标分解可由现有探针选型近似实现——探针打分时显式加连贯性/任务对齐分）。

## 6. 优先级判定：P2（背景）
理由：作为本批源头论文必须精读归档，其攻击机制与 JED 结构性不匹配（无库可毒、无梯度可用），不产生可直接落地的变体。但留下两条设计信条供 F011 执行时引用：①注入文案用自然任务词不用指令腔/混淆码（且有防御评测数据支撑）；②探针选型框架可借用其"目标动作×连贯性"双目标打分结构。若后续公榜实验发现语义伪装通过率不如预期，应回头对照本文 L_coh 消融检查是否连贯性不足所致。
