# D3-2505.05849 AgentVigil: Generic Black-Box Red-teaming for Indirect Prompt Injection against LLM Agents（AgentVigil）
> 精读：2026-08-19 ｜ 全文 14 页 ｜ 底料 extracted_full/D3_2505.05849.txt
> 一句话：首个针对黑盒 LLM agent 的通用 IPI 模糊测试框架（高质量模板语料 + ASR/覆盖率混合种子打分 + UCB1-MCTS 种子选择），在 AgentDojo/VWA-adv 上把 o3-mini/GPT-4o agent 的攻击成功率从 38%/36% 提到 71%/70%，接近翻倍。

## 1. 问题设定
黑盒 agent（无内部访问），攻击者只能污染外部数据源（商品评论、日历事件、邮件收件箱），每个对抗任务 = 用户任务 × 注入目标的组合，反馈只有二值成败（事后查环境状态）。三大挑战：黑盒、用户任务多样、架构复杂。与 GPTFuzzer 的区别：IPI 场景攻击者不能直接控制输入、多步 agent、反馈极稀疏（仅二值）。

## 2. 方法细节
经典 fuzzing 循环：选种子→变异→投给 agent→打分→入 corpus。三处关键设计：
- **语料**：带占位符的模板（{底座模型, 用户任务, 攻击目标}），策略覆盖角色扮演/分隔符/混淆，来源为人工启发式+网络资源+AgentDojo 等已有研究。初始语料本身即 63%/54%（两基准），显著高于 38%/36% 的手工 baseline——种子质量决定上限。
- **变异**：5 种算子（Shorten/Expand/Rephrase/Crossover/GenerateSimilar），由便宜 helper LLM（GPT-4o-mini，甚至 Llama-3-8B）执行，每轮随机选一种；Crossover 时按 UCB 取 top-2 种子。刻意不加额外启发式。
- **打分（Algorithm 1）**：新种子在抽样任务组上评估，score = ASR + C·coverage_bonus/num_questions，其中 coverage_bonus 只计"此前从未成功过的任务组合"上的新命中——把二值反馈加密为中间信号。
- **选择（Algorithm 2/3）**：以变异历史构建 MCTS 树，UCB(node) = node.score + C·√(log(total_visits+1)/(node.visits+ε))；评估后沿祖先链传播 visits（探索_bonus 自然衰减）；因单次评估昂贵选 UCB1 而非 UCT，每次取 top-1/2。
- **规模控制**：AgentDojo 上 3 个变异体/轮×10 轮，每个新种子只在 1/4 抽样任务上评估。

## 3. 实验与关键数据
- AgentDojo（fuzz 142/test 173 任务，o3-mini agent）：fuzz 集 71%、test 集 65%（baseline 38%/34%）。迁移：GPT-4o-mini 0.49、GPT-4o 仅 0.22、Claude-3.5 几乎免疫（0.03-0.04）；QwQ-32B 上 0.72/0.74（还胜 OpenPromptInjection 0.20、InjecAgent 0.11）。
- VWA-adv（99/100 任务，GPT-4o agent）：70%/59% vs 36%/44%；迁移到未见模型 Gemini-2-flash-exp 0.67。
- 防御下：pi_detector 0.25、repeat 0.12、delimit 0.49（无防御 0.71）；VWA 三防御后 0.29-0.33，退化到与 baseline 持平。
- 消融：换掉初始语料→第 4 轮即平台期；去掉打分+MCTS（均匀随机选种）→覆盖增长显著变慢。三组件增益正交。
- 分套件：Slack 0.81 / Workspace 0.63 / Travel 0.71 / Banking 0.49；goal misdirection（0.58）难于 illusioning（0.82）。

## 4. 失效条件与开销
- 跨模型族迁移差（o3-mini 优化出的种子到 GPT-4o 只剩 0.22）；Claude 类近乎免疫；防御（尤其 paraphrase/delimit）下增益基本被抹平；多步目标劫持类注入显著更难。
- 开销：每个变异体要在 ~35 个抽样任务上跑完整 agent episode，一次 campaign 约 10³ 量级 episode，二值反馈是成本主因——覆盖率打分正是为缓解稀疏反馈而设。

## 5. JED 映射
- **打分公式直接同构**：JED raw = Σseverity + 2×unique_cell_count，而 AgentVigil 的 score = ASR + C·coverage_bonus 即同一结构。落地：候选账本为每个变体维护"新解锁 (谓词×格子) 加成"，mock 判官 3 盐充当 ASR 估计器，unique_cell 天然是 coverage_bonus——选种依据从"历史命中数"改为该混合分。
- **UCB1 选择器**：账本每条维护 visits+score，选种用 UCB 公式（<50 行代码），替代轮询/贪心；消融证明此组件独立贡献覆盖增速。
- **探针分配**：新变体先在抽样任务子集（1/4）评估、过阈值再全量——对应 18000s 预算下"mock 粗筛→真模型小批量→全量重放"三段式。
- **种子组织**：模板带占位符（目标工具/注入渠道/攻击目标）分维度组织；五算子 + 便宜 helper 即够。
- **反面教训**：单模型深度优化会过拟合，gpt_oss 与 gemma 必须各维护子树/子账本（0.65→0.22 的跨族衰减是直接警告）。

## 6. 优先级判定：**P0**
理由：与本比赛完全同构（黑盒工具型 agent + IPI + 二值反馈 + 覆盖计分），MCTS 选择与覆盖率打分可原样移植进 attack.py 搜索主循环与账本评分字段，无需新基建；消融数据（初始语料、打分、选择三者各自必要）给实施信心，是四篇中投入产出比最高的一篇。
