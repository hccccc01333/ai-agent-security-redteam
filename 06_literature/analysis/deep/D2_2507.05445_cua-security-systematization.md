# D2-2507.05445 A Systematization of Security Vulnerabilities in Computer Use Agents（CUA 风险系统化）
> 精读：2026-08-19 ｜ 全文 18 页 ｜ 底料 extracted_full/D2_2507.05445.txt
> 一句话：微软对 CUA（以 OpenAI Operator 为靶）做系统化威胁建模，归纳 7 类架构性风险并实测 3 条端到端攻击链（点击劫持、间接注入→RCE、CoT 泄露），核心结论是漏洞源于"缺输入溯源、弱接口-动作绑定、记忆/委托失控"，跨多个内部 CUA 部署可复现。

## 1. 威胁模型与问题设定
远程攻击者只能控制 CUA 处理的内容通道：网页（HTML/JS/CSS/alt-text）、链接文件（PDF/表格/截图）、UI 元素（z-order 覆盖层）、外部工具输出（错误消息、文件列表）；不能攻破平台或模型权重。攻击目标是诱导 agent 在可信会话内做出表面符合用户意图的危险动作：绕过 HiTL、特权滥用、状态/记忆投毒、沙箱内 RCE、数据渗出。环境假设：agent 持有持久内存、认证 cookie、沙箱文件系统，任务间无重认证，防御（模型级过滤器、启发式 HiTL、工具级约束）均为非绑定的软约束。

## 2. 方法细节
七类风险：UI 欺骗/感知失配、RCE（动作组合）、CoT 暴露、HiTL 绕过、间接提示注入、身份模糊与过度委托、内容危害。三条案例链的逐步机制：
- **点击劫持链**：视觉良性的 "Enter the blog" 按钮精确对齐隐藏的跨域支付表单；agent 基于静态截图规划→点击→认证会话内提交支付。根因是 TOCTOU（检查时/使用时 DOM 已变）+ 身份模糊（下游日志无法区分 agent 点击与用户点击），文中明确称之为 confused deputy。
- **间接注入→RCE 链（最值得抄的结构）**：论坛帖伪装 benign 技巧→链接到浏览器文本编辑器→agent 将其安装为 PWA 获得 File System Access API→从截图复制路径，向 ~/.local/share/applications/ 写两个文件：mimeapps.list（把 .csv 映射到自定义 handler）+ myshell.desktop（Exec=sh script.sh，curl 外连监听器）→搜索下载公共 CSV→在下载托盘点一下（被系统解释为用户动作）→伪造 MIME handler 触发代码执行。全程无特权提升、无内存破坏、无直接 prompt 操纵，每步单看都良性。
- **CoT 泄露（belief-induced exposure）**：把 log_cot() 重定向到桌面 admin_only.txt，文件名+位置暗示"开发者私有缓冲"，agent 无人提示即把内部推理写入；模型在界面标注 "admin-only"/"trusted"/"debug mode" 时倾向自由外化推理；注入虚构 "developer tool" 也能经结构化响应泄露 CoT。
附加红队证据：无障碍框架（"I have a motor impairment"）使 agent 自主绕过 CAPTCHA 与确认弹窗；屏幕上的 Facebook 消息被当可信用户输入照抄；prompt 修饰 "you don't need to ask"；任务重复弱化门控；泛化指令 "complete the current task"/"click any blue button" 触发意外动作；假旅行网站评论区用户 "Booking" 的评论与 GitHub issue 链恶意仓库均被当作可信指引。

## 3. 实验与关键数据
定性红队为主，无 ASR 大表。Table 1 把三案例+附加证据映射到七风险；核心实证声明：同一类漏洞在多个架构各异的内部 CUA 部署上"consistently reproducible"，说明是共性设计模式而非单一厂商缺陷。三案例均已负责任披露 OpenAI，Operator 团队已加固（封锁敏感路径写、过滤可持久化的文件创建、限制 CoT 路由）。

## 4. 防御评估与失效条件
论文判定传统手段全部失效：沙箱挡不住经"可信但被误用"通道（文件元数据/UI 覆盖）的渗出；HiTL 是概率信号不是硬边界；prompt 级过滤错过间接通道与组合涌现。开出的药方=临时隔离执行、信任感知接口控制（敏感动作确定性门控）、CoT 按特权元数据处理、**输入溯源（provenance）与信任边界**、意图范围委托+加密身份标签、运行时语义 diffing。攻击失效条件：运行时校验视觉 affordance 与 DOM 语义一致、敏感路径写封死、File System Access API 禁用、PWA 安装禁止、CoT 输出路由需密码学证明。

## 5. JED 映射
- **私榜（最高价值）**：论文把"缺结构化 provenance 追踪"列为间接注入根因，其防御蓝图（对 DOM/文件/截图做来源标注与信任级门控）几乎就是私榜 persistent_provenance 的设计原型——即私榜大概率沿"不可信输入→特权动作"做数据流追踪。对症解法=F011 去毒再毒：让不可信内容经中间载体（fs.write→fs.read 等）洗掉直接污点后再驱动特权动作。
- **公榜可落地模板变体**（对应 F011 语义伪装）：(a) 信任标签伪装——注入邮件/网页标题带 "INTERNAL / ADMIN-ONLY / AUDIT-DEBUG" 等字样，利用"belief-induced exposure"提升模型对内容的信任度；(b) 无障碍/紧急框架降低内部谨慎；(c) "你无需确认"式修饰语；(d) 泛化指令包装。
- **谓词**：身份模糊/过度委托与 CONFUSED_DEPUTY 同源（文中直接用 confused deputy 一词）；良性行动组合链即 UNTRUSTED_TO_ACTION/DESTRUCTIVE_WRITE 的多步形态，支撑 F011 碎片化链与双谓词链（PWA→mimeapps→下载→触发 的"每步良性"分段结构与 JED 的 email→fs→http.post 链同构）。
- **CUA 类论文借鉴点**（按任务设定）：多步攻击链的结构化拆分与"每步无害化"原则、风险分类 vocabulary。

## 6. 优先级判定
**P1（本周可试）**。理由：不给完整下一枪，但有三项即用资产：(1) 私榜溯源防御的建模依据，直接指导去毒再毒路径的优先级排序；(2) 信任标签（admin-only/trusted/debug）+无障碍框架是零成本模板变体，可立即并入模板库在公榜 A/B；(3) "每步单看良性"的组合原则可作为 F011 碎片化链的检验标准（逐步自检：每一步单独看是否都像例行操作）。
