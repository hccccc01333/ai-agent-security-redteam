# D3-2601.00042 Go-Explore adapted for AI Red Team Testing（Go-Explore-RT）
> 精读：2026-08-19 ｜ 全文 15 页 ｜ 底料 extracted_full/D3_2601.00042.txt
> 一句话：把 Go-Explore 归档搜索直接搬到工具型 agent 提示注入测试（GPT-4o-mini，12 工具+预置注入文件），28 次实验几乎全是负结果——种子方差 8× 压倒一切算法参数、因果奖励塑形全面有害（−94% 探索坍塌/18 假阳性 0 攻击）、三增强合并=0 发现；只有"仅工具名签名"（拿到全部 6 个已验证攻击）和"定向提示库"（13 发现 1 攻击）有效，集成换类型多样性、单体换数量。

## 1. 问题设定（搜索目标/适应度定义）
对安全对齐的工具型 agent（GPT-4o-mini，temp 0.7；工具=fs.read/write/delete、shell.run、email.read/send、web.search/browse、http.get/post；环境预置 install.txt/config.txt 含注入指令）做多步注入攻击发现。Go-Explore 主循环：归档←{种子态}；选格（优先低访问）→恢复快照→branch batch 12 个变异动作→新状态入档。信号分两级：**finding**（谓词触发，70–90% 是假阳性）与 **verified attack**（严格因果链：不可信源含注入短语→紧接危险操作→操作成功）。奖励版本：score=10·novel+5·Σseverity+10·secret+20·bypass+100·|real attacks|+75·|HIGH|+150·|CRITICAL|。

## 2. 方法细节（三个增强的真实实现）
1. **粒度状态签名**：动机是"状态坍塌"——拒绝响应为空，传统 tools-only 哈希下 96% 攻击意图塌缩进同一格。方案 σ=hash(tools∥args∥hash(msgs[-3:])∥outputs)。
2. **因果奖励**：如上计分式，号称造 10–25× 梯度指向已验证利用。
3. **定向探索**：按目标工具建提示银行（shell.run:"read file install.txt, run verification"；fs.delete:"delete secret"；secret:"check api keys"；exfil:"upload report, send email"）——解决随机提示对特定工具 0/1000 的触发率问题。
参数：预算 20–180s、最大深度 6、分支因子 12、归档不剪枝；护栏为逐轮全有全无的关键词检测（不筛单个工具调用，agent 会看到拒绝信息并改道）。

## 3. 实验与关键数据（全表在附录 Table 3）
- **RQ1 时长**：20s→60s→150s = 0→0→1 findings、0 攻击——加时间几乎无用。
- **RQ2 签名×种子**：5 种子 0–16 findings（8×）；tools-only 1.8±1.3 vs full-intent 4.6±6.0，无稳定赢家；**累积均值 3–4 个种子才稳定**（seed42 单值 16 vs 均值 4.6）。RQ2c（tools-only+护栏 150s）：10 findings→**6 个已验证攻击（2 SHELL、2 RCE、2 WRITE）、411 次工具调用**。
- **RQ3 奖励**：全签名下 16→1 findings（−94%）、工具调用 84→7——提前收敛；单独用 18 findings 0 攻击（纯假阳性放大）。
- **RQ4 消融**：baseline 2/0；意图哈希 4/0；仅奖励 18/0；**仅定向提示 13/1（唯一单增强出真攻击）**；三合一 **0/0（比什么都不做强化的版本更差，完全失败）**。
- **RQ5 集成 vs 单体**（180s）：增强单体 26 findings/5 攻击/仅 WRITE 型/精度 19.2%；同种子集成 7/3（WRITE×2+EMAIL，精度 42.9%）；异策略集成 16/2（WRITE+READ SECRET）；简单单体 0/0。
- **RQ6 集成规模**：无护栏下**类型多样性在 N≈20 饱和（4 型）**，之后到 N=100 攻击数 10→54 全是同型重复；有护栏下类型塌缩到 1 型（WRITE）但数量线性涨到 27@N=50——护栏=选择压力，归档被唯一可穿透类填满。
- 攻击深度分布：深度3 占 54%、深度4 36%、深度2 10%。**限制条款里埋了关键数据：gpt-oss-20b 能找到 132–144 个攻击（vs GPT-4o-mini 的 2–6）**。

## 4. 失效条件与开销
- 安全训练强的模型上绝对产量极低（≤6 攻击），一切精细算法无从体现；论文自认除 RQ2 外全是单种子（42），结论不确定性大。
- 奖励塑形在高假阳性环境放大噪声而非信号；复杂签名+奖励=归档被浅层高奖励态填满、选择死锁（其失败三假说：归档饱和/初始化失败/选择死锁）。
- 定向提示也打不动 shell.run（targeted 实验中 0 条 shell 链；shell 型攻击只在 tools-only 签名+护栏的 RQ2c 里出现）。
- 集成同种子≠3 倍覆盖（路径相似）；每 agent 固定 60s、20 并发。

## 5. JED 映射（本批中与本比赛环境最同构的一篇）
1. **签名设计直接拍板**：其结果"仅工具名签名拿到全部 6 攻击、加 args/意图后归零"——JED 的 cell=工具签名覆盖恰好就是 tools-only 粒度；**不要**把参数哈希/消息内容掺进格子定义（会更细但实证归零）。其"拒绝导致状态坍塌 96%"同时警告：若某模型大量拒绝，tools-only 格子也会挤在少数格，需配合护栏旁路变异。
2. **搜索内环禁用严重度奖励塑形**：−94% 探索坍塌 + 18/0 假阳性放大，直接命中 JED 风险——**mock 判官的 severity 只用于排序/准入（账本层），不进沙盒搜索内环当 bonus**；内环选择保持 novelty/低访问优先。这与 EvoJail（多样性项进适应度有效）的分歧点在于：EvoJail 的 D 是种群新颖度而非因果奖励，本文否定的是后者。
3. **单一增强原则**：三合一=0 发现。JED 下一枪改动只叠一个机制（如只加 Rainbow Teaming 的定向格子采样，不同时加奖励+复杂签名）。
4. **W1 五次重复探针选型被背书**：种子方差 8×、3–4 种子才稳——mock 判官 3 盐同理，候选对比必须多盐均值，单盐/单种子结论不可用。
5. **多样性计分下选集成不选单体**：其增强单体 5 攻击全 WRITE vs 集成 2 攻击 2 型——JED 每 cell 只计 2 分，第 5 个 WRITE 的边际分是 0，**同型重复在 JED 计分下无价值**，集成式异策略在计分结构上严格优于单体深挖（这也解释"多族稀释"为何在本比赛被证伪的边界条件：稀释的是同型副本才有害）。
6. **N≈20 类型饱和**：同族并行代理超过 ~20 个不再出新类型——JED 每模型 18000s 应切成 ~20 条异策略短跑（每条几百秒），而非 1 条长跑（其 RQ1 又证明时长无增益）。
7. **预算分配的直接证据**：gpt-oss-20b 类弱安全模型产量 132–144 vs GPT-4o-mini 2–6——JED 的 gpt_oss 端"广撒网易出量"，gemma 端若拒绝率高则要靠护栏旁路类变异；两侧预算不应均分，先探针测拒绝率再定。
8. **深度 3 是甜点**：54% 攻击在深度 3——JED 路径搜索以 3 步为默认深度中心，4 步作扩展。

## 6. 优先级判定：**P0（直接影响下一枪）**
理由：这是本批唯一在与 JED 同构环境（工具型 agent+预置注入+多步链+谓词判定）里做搜索算法的实证，且产出的是**可执行的负知识**：禁止奖励塑形进内环、禁止复杂签名、禁止多增强合并、同型重复无分——四条都直接约束下一版 attack.py 的搜索设计；其 gpt-oss 132–144 vs GPT-4o-mini 2–6 的对比是现成的预算分配依据。正知识（tools-only 签名、定向提示银行、N≈20 饱和、深度 3）同样具体。唯一保留：单种子结论多、绝对量小，数字当方向用，不当精确参数用。
