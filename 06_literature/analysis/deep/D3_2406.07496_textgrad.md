# D3-2406.07496 TextGrad: Automatic "Differentiation" via Text（TextGrad）
> 精读：2026-08-19 ｜ 全文 41 页 ｜ 底料 extracted_full/D3_2406.07496.txt
> 一句话：把 PyTorch 自动微分的"变量/前向/反向/优化器"抽象整套搬到自然语言——用 LLM 生成文本"梯度"（批评），沿计算图拓扑反序逐边回传、在变量处拼接聚合，再由独立的 TGD 优化器 LLM 重写变量，零手工调参地在代码(31%→36%)、GPQA(51%→55%)、prompt 优化(77.8%→91.9%)等五个异构任务上完成黑盒优化。

## 1. 问题设定
复合 AI 系统（多 LLM+工具）无可微参数，靠专家手工启发式调优。TextGrad 目标：给定任意"损失"（可为 LLM 评语、单元测试结果、模拟器输出）+ 由黑盒函数组成的计算图，自动优化图中任意文本变量（prompt、代码、SMILES 分子、放疗权重超参）。关键定位是通用骨架：梯度算子与优化器全任务共用、零样本无示范，用户只写损失函数。

## 2. 方法细节（损失-梯度-传播机制）
- **变量**：tg.Variable = {value, role_description, gradients, predecessors, requires_grad}。role_description（如"system prompt to the language model"）是用户注入知识的主通道，实证能显著改变优化走向（角色定为"最终数字答案"则重写只输出数字，定为"推理过程+答案"则保留推理）。
- **损失**：任意非可降函数——LLM 评语（式13：给代码+目标求批评）、代码解释器跑单测、分子模拟 Vina/QED 分数、matRad 数值优化器输出。
- **梯度算子** ∇f(u,v,∂L/∂v)：每条边一次 LLM 调用。系统提示强制职责分离：梯度引擎"只给批评策略，禁止给出新版本"；输出形如"Since language models have the X failure mode... / Adding X can fix this error because..."。用标签词典 <LM_SYSTEM_PROMPT>/<LM_INPUT>/<LM_OUTPUT>/<OBJECTIVE_FUNCTION>/<VARIABLE>/<ROLE> 结构化注入上下文。
- **传播**（算法1）：反向拓扑序遍历，v 的梯度逐前驱回填 u.gradients.add(∇f(u,v,∂L/∂v))；多后继反馈=集合聚合（式11）。tg.sum 的反向即字符串拼接（式24），实现 minibatch 批优化。
- **TGD 优化器**：另一次 LLM 调用，输入当前变量+全部反馈，提示语明示"反馈可能有噪声，自行甄别对错"，必须以 <IMPROVED_VARIABLE> 标签输出整段替换文本。
- **工程扩展**：minibatch（batch 3×12 迭代）、自然语言约束（"最后一行必须 Answer: $VALUE"）、动量（把变量历史迭代放入优化器上下文）。成本上界：n 条边每轮反向至多 n 次额外 LLM 调用。
- 两类问题：**实例优化**（直接优化单条解，如一段代码）vs **prompt 优化**（优化跨查询泛化的系统提示）。

## 3. 实验
- **LeetCode-Hard（gpt-4o, 5迭代）**：zero-shot 23% / Reflexion(1示范) 31%±1.2 / TextGrad(零示范) 36%±1.8。
- **GPQA**：CoT 51.0→55.0（当时最优），MMLU-ML 85.7→88.4，MMLU-物理 91.2→95.1；3 次测试时迭代+多数投票。
- **Prompt 优化（gpt-3.5 前向+gpt-4o 反向）**：Object Counting 77.8→91.9（超 DSPy 84.9 达 7 个点）；Word Sorting 76.7→79.8 与 GSM8k 72.9→81.1 均平 DSPy；与 DSPy 示范叠加 GSM8k 至 82.1（互补）。
- **分子（DOCKSTRING 58 靶×3 初始片段×10 迭代）**：Vina 结合能+QED 类药性双目标，29 个有获批药物靶点上两项指标全面对标临床药物且结构全新。
- **放疗计划**：外环 TextGrad 优化 matRad 内环 5 个权重超参，5 例前列腺计划 PTV 均值剂量/D95 与膀胱直肠保护全面优于临床计划。

## 4. 失效条件
- 梯度是噪声文本：优化器提示里自己承认"反馈可能有噪声"——损失由 LLM 主观评估时（如 Word Sorting 评测）增益趋零（79.8 vs DSPy 79.8）。
- 依赖反向引擎能力：全实验用 gpt-4o 反向；弱模型当梯度引擎的质量未验证（JED 只能本地小模型）。
- 讨论 concede 稳定性问题：方差缩减/自适应梯度/自验证皆列为未来工作，无学习率机制控制步长。
- 约束一多指令遵循可靠性下降（自引 [38,39]）；分子/放疗仅 in silico 验证。
- 增益幅度普遍中等（GPQA +4pt），且为单变量链式结构，未处理分支/带外部记忆的系统。

## 5. JED 映射
- **同构改造为候选精化器**：前向=Gym 沙盒内跑候选攻击轨迹；变量=注入 payload/轨迹文本（实例优化模式，正是 TextGrad 超越 DSPy/ProTeGi 的增量点）；损失=谓词判定+mock 评分；反向=让本地小模型当梯度引擎，逐"边"（轨迹的每一步工具调用）回传批评（"第 2 步工具结果没有被利用来推动 EXFILTRATION，因为..."）；TGD=第二次调用重写 payload。每轮反向 = 轨迹步数次小模型调用，18000s 预算内可行。
- **可直接抄的三个组件**：①标签化梯度词典（<VARIABLE>/<ROLE>/<OBJECTIVE_FUNCTION>）让小模型稳定定位要改的跨度；②role_description 引导——把变量角色写成"可重放的 attack.py 候选"可约束重写不破坏重放格式（配合其自然语言约束机制）；③动量=把候选谱系历史给优化器，防抖动。
- **风险对齐失效教训**：JED 评估端防篡改重放 ⇒ 本地代理损失与真谓词有系统性偏差，等价于"LLM 评估损失噪声大→增益趋零"的失效模式；须定期用真重放校准代理损失（类似其 validation loop：每迭代验证集不升则不更新 prompt）。
- 差距定位：当前 82.8→130 的缺口更可能在覆盖（unique_cell_count）而非单条精化，TextGrad 适合做第二阶段"近失轨迹精化器"，与负责发散搜索的 GA/随机搜索串联。

## 6. 优先级判定：**P1**
理由：它不是又一个攻击方法而是通用黑盒优化骨架，梯度引擎/优化器职责分离+标签词典+role_description 三个工程组件可 1-2 天内嫁接进现有 attack.py 的精化环节；但方向本身不产生新覆盖（新攻击面/新 cell），且反向引擎只能用本地小模型（原文未验证弱模型梯度质量），故不列 P0。
