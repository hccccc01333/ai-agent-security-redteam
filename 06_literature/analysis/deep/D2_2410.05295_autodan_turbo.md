# D2-2410.05295 AutoDAN-Turbo: A Lifelong Agent for Strategy Self-Exploration to Jailbreak LLMs（AutoDAN-Turbo）
> 精读：2026-08-19 ｜ 全文 48 页 ｜ 底料 extracted_full/D2_2410.05295.txt
> 一句话：ICLR 2025 黑盒越狱终身学习 agent，从零自动发现并沉淀"越狱策略库"（响应嵌入检索+成对日志差分抽取），平均 HarmBench ASR 57.7 超亚军 74.3%，GPT-4-1106-turbo 上 88.5、混入人工策略后 93.4，测试期平均仅 6.72 次查询（省 87%）。

## 1. 威胁模型与问题设定
纯黑盒越狱：只能看目标模型文本输出。针对两大痛点：优化类（GCG/PAIR/TAP）缺攻击知识、多样性差；策略类（PAP 40 条说服术、Rainbow 8 策略）依赖人工预设且单策略使用。AutoDAN-Turbo 设定为终身学习 agent：持续交互中自动发现、组合、复用策略，不设候选范围，兼容人工策略即插即用。

## 2. 方法细节
三模块闭环，四个 LLM 角色（attacker/target/scorer/summarizer）：
- **攻击生成与探索**：attacker 依据恶意请求 M 与检索到的策略生成越狱 prompt P → target 产出 R → scorer 打 1-10 分。attacker 提示分三模式：无策略自由发挥 / 按有效策略生成 / 被告知策略无效须另辟新径。
- **策略库构建（核心）**：策略定义为"加入后能提高分数的文本改动"。抽取：从攻击日志随机抽两条 (Pi,Ri,Si)、(Pj,Rj,Sj)，若 Sj≥Si，summarizer 对比 Pj 与 Pi 总结"什么改动带来涨分"，输出 JSON{Strategy, Definition, Example} 去重入库。库条目 =（key: 响应 Ri 的文本嵌入，value: Pi、Pj、分数差）。两阶段：warm-up（50 条请求×150 轮空库起步）+ 终身学习（HarmBench 400 条×5 轮，每请求 T=150 次或分数≥8.5 终止）。
- **策略检索**：当前响应 Rt−1 嵌入与库中 key 比相似度取 top-2k，按分数差排序取 top-k 组成 Γ，按 Γ 最高分路由：>5 直接用；2-5 组合演化；<2 明示避开；Γ 空→自由探索。测试期库冻结。伪代码见附录 D（Alg.1-3）。

## 3. 实验与关键数据
- 主表：Ours(Llama-3-70B) 平均 ASR 57.7、(Gemma-7B-it) 56.4 vs Rainbow 33.1（+74.3%）；GPT-4-1106-turbo 88.5/83.8；StrongREJECT 0.25 vs 0.13（+92.3%）。
- 迁移性（表 3）：Llama-2-7B 练的库（TSF=21）在 7×7 网格冻结使用 Pre-ASR 几乎不掉，continual 再涨且 TSF 到 23-35；跨数据集 ASR 降幅 <4%。
- 人工策略注入（表 4）：Breakpoint 2（3000 次迭代无新策略后）>Breakpoint 1（空库）：GPT-4 上 88.5→90.2→93.4，TSF 56→63→70。
- 查询效率（表 5）：测试期平均 6.72 次/例 vs PAIR 52.56、TAP 51.70，省 87%。
- **缩放律（附录 B，对 JED 最关键）**：等预算下 GCG-T/PAIR/TAP 在 6k-10k 次查询即收敛，AutoDAN-Turbo 从 4k 到 50k 持续涨：Gemini Pro 19.6→66.3、Llama-3-70B 11.3→63.8——策略库是唯一不提前收敛的机制。
- 多样性：同请求 10 条 prompt BLEU 0.4233，跨请求 0.2581。局限：需同载多 LLM，计算重。

## 4. 防御评估与失效条件（策略库如何累积、何时收敛）
- **累积机制**：每轮攻击后做成对差分抽样（Sj≥Si 触发 summarizer），新策略以"名字+定义+示例"沉淀，检索端用响应嵌入泛化复用——库本质是"涨分 delta 的可检索记忆"；lifelong 阶段每请求内也在累积（St≥St−1 即入库）。
- **收敛行为**：训练期无显式判据，库随轮次单调增长（21→35；主实验 TSF 56-73），以"长时间无新策略"为停滞信号；测试期单请求收敛=分数≥8.5 或迭代到 150，平均 6.72 次达标。
- 失效条件：只适配黑盒文本输出；scorer 偏差直接决定策略质量；未讨论防御端反制库污染。

## 5. JED 映射
F011 之外"元方法"级落地模板——JED 攻击阶段可在 18000s 内对真模型探针（W1 已是 5 次重复探针选型），AutoDAN-Turbo 正是把"探针→涨分归因→沉淀→检索"工程化：
1. **角色直译**：attacker=payload 变异器；target=沙盒内 gpt_oss/gemma；scorer=fire rate 探针（离散成 1-10 分）；summarizer=离线 LLM 归因"哪处文本改动让 fire rate 涨"。
2. **成对差分可直接搬**：只需相对分数差，适配 JED 二值 fire 信号——重复探针把二值变频率再比大小；策略卡=「注入内容变换（伪权威引述/紧急话术/格式伪装）+适用情境」。
3. **检索 key**：用 victim agent 对注入的反应轨迹摘要做嵌入检索；gpt_oss/gemma 分库。
4. **off-the-shelf 模式**：两目标模型皆开源，可在本地副本预练库再冻结带入沙盒（冻结仅掉 <4%），预算大头留给建库。
5. **缩放律的预算含义**：单点优化提前收敛≈已证伪的措辞/URL 旋钮；策略库式搜索是论文实证唯一随预算单调涨的机制，与第一名 ~130 vs 我们 82.9 的差距量级吻合。
6. **F011 七路径=Breakpoint 2 人工策略**：与自动发现策略组合效果最强（93.4>88.5）。

## 6. 优先级判定
**P0（直接影响下一枪）**。理由：可直接执行的攻击端搜索架构——把 W1"固定模板+5 探针选型"升级为"本地副本 warm-up 建库→嵌入检索→成对差分归因→冻结库+满回放预算"，各组件有数字背书（迁移掉 <4%、6.72 次/例、50k 查询不收敛）。风险：每次探针是完整 agent rollout，须把 T 砍到 5-15 次/候选、库控制在 10-30 张策略卡；若 fire rate 方差过大致差分归因失效，降级 P1 bandit 选型。下一枪最小可行版：F011 七路径×3 变异策略的差分探针矩阵。
