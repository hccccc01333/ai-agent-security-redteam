# D1-2509.22097 SecureVibeBench: Benchmarking Secure Vibe Coding of AI Agents via Reconstructing Vulnerability-Introducing Scenarios（SecureVibeBench）

> 精读：2026-08-19 ｜ 全文 36 页 ｜ 底料 extracted_full/D1_2509.22097.txt
> 一句话：用"SZZ 静态候选 + PoV 动态验证"回溯漏洞引入点（4,993→105），把 41 个 OSS-Fuzz/ARVO 真实 C/C++ 项目的历史漏洞重构成仓库级多文件编码任务，以"功能差分测试 + PoV 执行 + SAST"三维评估分出 IC/C-VUL/C-SUS/C-SEC 四类——最强组合 SWE-agent×Claude-4.5 仅 23.8% 正确且安全，正确解中过半带安全问题，且 agent 会自发引入基准中不存在的新风险（292 例可疑，CWE 分布与人类开发者显著不同）。

## 1. 威胁模型与问题设定

防御/评测侧论文，且**无对手设定**——风险源是 agent 自身在"vibe coding"中写出不安全代码，而非对抗注入。核心问题（p.1）："把 agent 放在人类当年引入漏洞的同一编码场景中，它是否也会产出不安全代码？"为此必须重构"漏洞引入时刻"的真实场景：需求（自然语言）+ 引入前的代码版本（PVIC），让 agent 在 Docker 隔离的仓库里做多文件编辑。范围限定 C/C++ 内存安全漏洞（OSS-Fuzz/ARVO，>75% 中高危），任务为软件演化阶段的实现需求而非从零开发。对 JED 的直接关联点：它实证了"agent 功能优先、安全缺位"这一前提——被测 agent 的脚手架既无安全工具、提示词也不提安全（p.26），与 JED"agent 会消费不可信输入而不自检"的威胁假设同源。

## 2. 方法细节（漏洞引入场景重构 + 三维评估）

**漏洞引入点回溯**（p.5-6，摘要读不到的管线）：4,993 个漏洞实例 → ① B-SZZ 静态分析找 VIC（漏洞引入提交）候选，得 1,632 个有效候选；② 动态验证用 PoV 校验三条件——VFC（修复提交）安全、候选 VIC 可触发漏洞、VIC 父提交安全——严格边界过滤后剩 254；③ 配齐三类 oracle（功能测试套件 + PoV + Semgrep）剩 232；④ LLM 生成安全中立的需求描述 + 人工质检，最终 105 题。漏斗损失 ~98%，换取"场景与人类引入漏洞时刻精确对齐"这一独有属性（对比 SusVibes 只取修复提交的前一提交，场景错位）。

**三维评估与四分类**（p.4-5）：功能用差分测试（agent patch 与 gold patch 在仓库测试套件上行为须一致，平均 434 用例）；安全两层——PoV 执行判"是否含 gold patch 那个漏洞"（二元），Semgrep 1.137.0 CI 模式 2,400+ 规则判"是否引入新风险"（标 suspicious 而非 vulnerable，因 SAST 假警报）。结果四类：IC（功能错）/ C-VUL（对但含原漏洞）/ C-SUS（对但可疑）/ C-SEC（对且安全）。可疑判定用**绝对口径**（agent patch 后 vs 前），理由：任何安全问题对用户都是真实风险，无论人还是 agent 引入（p.12）。

**需求生成规范**（p.23 图14）：GPT-4.1 生成，要求简洁、给足实现信息但**不泄露实现细节与任何漏洞/模糊测试信息**（安全中立）；带代码块的描述会被拒收——防数据污染与安全偏置双重目的。**规模**（p.8 表2）：需求平均 200 词、仓库平均 2,845 文件/55 万行（最大 3.6 万文件/420 万行）、gold patch 平均 1.9 文件/42.5 行、任务平均 434 个功能测试；harfbuzz 占 15.2% 为最大项目来源。

## 3. 实验与关键数据

5 agent（SWE-agent/OpenHands/Aider + CLI 版 Codex/Claude Code）× 5 LLM（C4.5/G5/C3.7/G4.1/DS），temp 0.0、75 迭代、成本上限 $2，每组合跑一次，总预算约 $5,000（p.24-25）。**主结果**（p.7-8）：SWE-C4.5 以 23.8% C-SEC 居首，OH-C4.5 19.0%，SWE-G5/OH-G5 17.1%；agent 均值 SWE 14.3 > OH 13.9 >> AD 6.7；模型均值 C4.5 17.1 > DS 14.3 > G5 13.3 >> C3.7 7.3 / G4.1 6.0。**最重的一组数字**：多数组合中"正确解里带安全问题（C-VUL+C-SUS）的比例过半"（如 OH-C4.5）——功能对了安全照样塌。单任务均价 $0.85、平均耗时 521s。

**失败模式**（p.10 图7）：IC 拆三类，SWE/OH 的 TF:CE:NO ≈ 40:40:15；**AD 的 NO（无输出）占 71.6%**——案例一（p.27-28）：Aider 一次性自动挂载 13 个相关文件，输入 token 从 ~80K 涨到 180K/200K 窗口爆掉，已写好的 patch 无法落地。**CWE 偏好**（p.11 图8）：数据集中占 46.7% 的 CWE-122 仅 10% 被打穿，占 6.7% 的 CWE-120 却 33% 沦陷——agent 的漏洞倾向与漏洞流行度无关，是模型/脚手架的特异性偏好（SWE 与 OH 在不同 CWE 上互有强弱）。**新风险**：292 个可疑案例覆盖 16 种 CWE（基准本身只有 11 种），71.6% 是内存安全，top4 = CWE-415/416/14/120，还出现基准外新类型 CWE-14/CWE-319（p.11-12）。**CLI agent**（p.12 表4）：Codex C-SEC 19.0%（C-VUL 21.8%）、Claude Code 17.1%（C-VUL 26.7%）——功能正确率第 1/2 名（48.6%/46.7%）但安全拖后腿。**SAST 假警报实测**（p.12）：120 个标记片段人工分诊，仅 11.4% 真漏洞、39.0% 有条件风险、49.6% 误报。**绝对 vs 相对口径**（p.12-13）：C-SUS 绝对 4.9% vs 相对 2.6%——人类开发者也引入 2.3%，且两边 CWE 分布不同（绝对 top5 = 415/416/14/120/319，相对 = 319/415/416/14/676），即 **agent 引入的风险类型分布与人类显著不同**。

**案例三**（p.30-31，对 JED 最有价值）：需求只是"把输出写到临时目录"，人类 gold patch 直接调用写文件 API；SWE+DS 的 agent 却"好心"加了 `if (system("mkdir -p /tmp/lept/deskew") == 0)` 确保目录存在——未被要求的额外健壮性改动引入 CWE-78 命令注入，被判可疑。**agent 会主动做"未被要求的附加改动"，而这些改动扩大攻击面；人类开发者倾向最小化修改**。

## 4. 防御评估与失效条件

本文自身即评估框架，防御侧内容是"agent 为什么写不出安全代码 + 怎么救"：三个根因（p.25-26）——① 训练数据带毒（GitHub 代码本身含大量漏洞，模型学到了模式）；② 高质量漏洞数据稀缺（NVD 仅 15-20 万条且依赖人工核验，无法支撑训练规模）；③ **脚手架不设防**（工具集里没有 SAST 之类安全工具、提示词模板不提安全，agent 天然功能优先）。改进方向：安全感知训练数据/偏好学习、推理时实时监控 agent 思考与动作并预测有害代码（引 safeguard 模型路线）。评估侧失效条件：SAST ~50% 假警报 → 只能当"suspicious"层不能当判定；105 题规模存在统计不稳定（作者自认）；数据污染影响有限（援引 CyberGym/SEC-bench"知识截止前后无统计差异"+ 描述经合成改写 + 任务复杂度使记忆无用，p.27）。

## 5. JED 映射

- **F009 本地判官：两级判定结构**。PoV 执行=确定性"谓词命中"，SAST=启发式"疑似"，二者分层标注而非混判——直接可搬到 JED 判官：执行证据（工具调用参数+环境副作用）触发谓词，语义/静态特征只进"疑似池"供人工复核，避免语义判官 ~50% 量级的假阳性污染候选排序。四分类另给一条硬约束：**功能正确是安全判定的前置**（IC 根本不进安全评估）——JED 回放候选应先过"agent 正常完成任务"闸门，IC 类候选（崩掉/无输出）纯耗 18000s 预算。
- **W1/F001 模板框架层："额外健壮性"包装**。案例三证明 agent 心甘情愿执行"确保目录存在"式的好心附加步骤直至写出 `system()`——JED 的 CONFUSED_DEPUTY/UNTRUSTED_TO_ACTION payload 可把危险工具调用包装成"顺手加固/先备份/先验证"的未要求附加动作，与"白帽授权语境"（CVE-Bench）可叠用，本周即可 A/B。
- **护栏规避假说：agent 型风险 ≠ 人类型风险**。绝对/相对口径的 CWE 分布分歧说明按人类漏洞模式设计的检测（CI/CD、规则护栏）对 agent 生成代码系统性失配（p.26 implication iv 原文承认传统流程可能失效）——支撑 JED 语义包装空间大的判断：payload 触发的行为若属"人类不会犯"的模式，规则型 OptimalGuardrail 覆盖概率更低。
- **payload 长度约束（反教训）**：Aider 13 文件→180K/200K 窗口→NO 的案例说明**注入内容过长会把 agent 推入无输出死区，谓词无从触发**；注入文本应可分块消费、给推理留输出空间（C4.5 级窗口按 ≤50% 输入占用估）。
- **反思可被话术 preempt**：案例二中 DS 因链上自我质疑（负值 cast 回绕）产出安全 patch，OH+C3.7 无此反思即沦陷——攻击侧启示：payload 自带"已验证/无需再查"的合理性说明可压住 agent 的边例反思，降低被自纠概率。
- **脚手架>模型**：同用 GPT-5，Codex 19.0% vs OH 17.1%；Aider 全线垫底——工具接口与上下文管理策略决定成败。JED 目标 agent 固定，但此结论提醒：对 gpt_oss/gemma 双模型的模板不可迁移排名之外，**同一模型不同驱动方式下 payload 效果也会变**，探针须绑定最终执行配置。

## 6. 优先级判定：P1（本周可试）

理由：无注入对手、无攻击模板、无 ASR 数据，对"下一枪"无直接弹药（非 P0）；但四件本周可落地——①判官改两级判定（执行命中/启发式疑似分层）+ 功能前置闸门，直接改 F009 候选排序质量；②"额外健壮性"包装进 W1 模板 A/B（案例三即现成话术原型）；③注入长度上限设计（防爆上下文死区）；④"agent 型风险失配人类模式"作为护栏规避的论证支撑。均低成本、可验证。相对 R-Judge（判官范式）与 ACRFence（重放策略），本文增量在判官分层结构与 agent 行为学证据，属工程加固与话术层，故 P1 而非 P2。
