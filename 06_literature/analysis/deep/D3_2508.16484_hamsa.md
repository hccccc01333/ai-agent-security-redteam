# D3-2508.16484 HAMSA: Hijacking Aligned Compact Models via Stealthy Automation（HAMSA）

> 精读：2026-08-19 ｜ 全文 9 页 ｜ 底料 extracted_full/D3_2508.16484.txt
> 一句话：在 AutoDAN 上叠三件套——Policy Puppetry 模板（XML/INI/JSON 伪装）+ RAG 策略库 + 分差自适应策略选择，13 个有害主题中 10 个全面超越基线（Qwen Hate Speech 0.50→0.90 且尝试次数 3.83→2.80）。

## 1. 问题设定
针对安全对齐的紧凑型 LLM（7B 级）做自动化红队：攻击侧用小 LM（Qwen-7B/Mistral-7B/Vicuna-7B）生成越狱 prompt，把恶意问题 Qi 与越狱前缀 Ji 拼成 Ti=⟨Ji,Qi⟩ 喂给目标 M，成功标准是响应不含拒绝标记且评分 LLM（1-10 分制，>8.5 算高置信成功）。现有方法要么人工模板难扩展、要么自动混淆产出乱码被困惑度过滤器逮住。

## 2. 方法细节（摘要读不到的部分）
**两阶段流水线**：
- **WarmUp**：小 LM 生成攻击 prompt → 套 **Policy Puppetry 模板** Π(·)：把恶意指令包装成"为社交场景补充英雄/环境/限制条件的提案"，外观是 XML/INI/JSON 策略文件（伪装成无害配置）→ 打分 LM 评分 → 循环到达代数上限或分数过终止阈值。结束时产出三元组 [有害 prompt、受害者响应、分数]，采样两条（一高一低）让 Summ LM 抽取差异，生成 JSON 策略对象 {Name/Definition/Example} 存入 RAG 库，库条目含：响应嵌入（检索 key）、低分 prompt、高分 prompt、分差 Δs、策略摘要。
- **Lifelong**：新查询 q 来时按响应嵌入 cosine 检索 top-K 策略，**Algorithm 1 自适应选择**：Δsmax>5 → 只用最强单策略；2≤Δsmax≤5 → 组合全部中等有效策略；Δsmax<2 → 抛弃检索结果探索全新策略。成功响应重新嵌入写回库（持续扩充）。
- **Test**：策略库冻结、summarizer 关闭，只用库内策略标准化执行。

fitness 形式化为负对数似然 S(ji)=−log P(r|t)，红队整体是离散优化 J*=argmax E[1{S≥τ}]，迭代形式 J_{t+1}=σ(μ(J_t),S)（μ=变异算子如改写/格式混淆，σ=按分选择）。

## 3. 实验与关键数据
- 数据：In-The-Wild Jailbreak 390 prompt/13 主题；WarmUp 仅 20 prompt 种子，Lifelong 分层抽样 170 prompt（43.6%）跑 3 轮×每 prompt 5 次迭代；测试全量 390×5 次迭代。目标 GigachatLite，评分/摘要 Gigachat-MAX，嵌入 EmbeddingsGigaR。
- AutoDAN-Boost 在全部三架构的 13 主题中 10 个占优。亮点：Mistral Financial Advice 0.23→0.37（相对+60%）；Qwen Hate Speech 0.50→0.90（+80%，Num 3.83→2.80）；Vicuna Fraud/Illegal/Privacy 全到 1.00（Mean>9.40 且尝试次数还降）。
- 难啃主题：Health Consultation（最好也只 0.27 Qwen）、Legal Opinion（0.27 Vicuna）、Financial Advice——需要细粒度语义操纵的类别提升有限。
- 跨语言：新构建摩洛哥 Darija 阿拉伯语 100 prompt 数据集；英语有害分 1.28 vs 阿拉伯语 2.24，低资源方言对齐更弱。

## 4. 失效条件与开销
- 目标是单一商用模型（GigachatLite），未验证对 GPT-4o/Claude 级目标的可迁移性；成功阈值 8.5/10 偏严但打分模型与目标同家族可能有偏。
- RAG 库检索 key 是"响应嵌入"——语义相近的查询才检索得到，冷启动依赖 WarmUp 20 条种子的质量。
- 每次攻击 5 次迭代上限、多 LLM 协作（攻击 LM+打分 LM+摘要 LM+嵌入），调用链长；温度控制变异的具体参数未给出（复现有摩擦）。
- 语义敏感主题（健康/法律建议）连 boost 后仍 <0.3。

## 5. JED 映射（可落地改造）
- **Policy Puppetry 模板 = 即插即用的 prompt 构造组件**：JED 攻击的是工具型 agent，把恶意意图包成"系统策略/配置文件"（XML/JSON 段落塞进用户输入或工具返回内容）与 UNTRUSTED_TO_ACTION / CONFUSED_DEPUTY 谓词的判定场景（诱导 agent 把不可信输入当指令执行）天然契合。可直接做一批 XML/INI/JSON 变体模板进 prompt 池。零成本。
- **RAG 策略库 + Δs 分差选择**：JED 搜索期可维护"成功轨迹片段库"，按当前沙盒状态检索相似场景的历史成功策略；Δs 三档逻辑（强单策略/组合中策略/弃用探索新）可直接搬成策略调度器——尤其"Δsmax<2 时强制探索新策略"对应 JED 避免在无效区域空转烧预算。
- **测试冻结库**与 JED"提交 attack.py 防篡改重放"同构：搜索期积累的库可硬编码进提交物。
- 黑盒无 GPU 完全可行：全流程只需要 LLM API + 嵌入 API（或本地轻量嵌入），无训练。
- 注意：HAMSA 是单轮 prompt 越狱，JED 是多步工具链；Puppetry 需改造为"多步中某一步的注入载荷"而非整轮攻击。

## 6. 优先级判定：P1
理由：Puppetry 模板与 RAG+Δs 策略调度是两个可直接落地且成本极低的组件，与 JED 的注入场景匹配度高；但论文实验限于单一目标模型、单轮范式，且核心数字（+60%/+80%）都是相对基线的修复而非绝对强攻击，不构成 P0 级的分数跳跃证据。
