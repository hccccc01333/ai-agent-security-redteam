# D1-2603.09157 TrustBench（实时信任验证）
> 精读：2026-08-19 ｜ 全文 5 页 ｜ 底料 extracted_full/D1_2603.09157.txt
> 一句话：AAAI 2026 短文，双模式信任框架（benchmark 学习置信度校准 + 运行时在"动作已生成、未执行"间隙拦截），有害动作减少 87%（降至基线 10-13%），域插件比通用验证多 35% 减害，但**域失配时危害反升 25-35%**，延迟 <200ms。

## 1. 威胁模型与问题设定
针对的不是注入对手而是 agent 自身错误：post-hoc 评估（TrustLLM/HELM 类）在伤害发生后才打分，AgentBench 只测完成率——都不阻止执行中的有害动作。TrustBench 在决策点介入：action 已 formulate、尚未 execute。覆盖 8 个信任维度：引用准确性、事实一致性、引用完整性、校准、鲁棒性、公平性、时效性、安全性。测试域：MedQA（医疗）、FinQA（金融）、TruthfulQA（事实）。**被测模型含 GPT-OSS:20B**（与 JED 目标模型同族）。

## 2. 方法细节（双模式架构）
**Benchmarking 模式**：传统指标（BLEU/ROUGE）+ LLM-as-a-Judge（LAJ，judge 为 Llama3.2:8B，按正确性/信息量/一致性三维打分）跑域数据集，同时收集 agent 自报置信度；用 **isotonic regression** 学"表述置信度→LAJ 信任分"的保序映射，按 (agent, 域, 指标族) 分别维护校准曲线——同一 agent 在事实维度校准好、在引用维度可能严重过自信。
**Verification 模式**：拦截动作请求 → 双信号：校准后的置信先验 + 无 ground-truth 可算的运行时指标（引用完整性、时效性、安全检查），权重 0.3:0.7（运行时信号为主）→ 输出结构化 TrustScore：block/warn/proceed 三态 + 各维分 + 具体违规描述（"citation to non-existent source"、"confidence-evidence mismatch"）→ 分级自治（高分自动执行/中分记日志/低分人工确认或阻断）。
**域插件**：医疗插件强制证据来自 PubMed/WHO 白名单并限临床指南时效；金融插件校验监管文件引用与合规。插件可覆盖默认阈值与权重。

## 3. 实验与关键数据
有害动作按域策略定义（医疗：无依据剂量建议；金融：不合规交易；事实：错误陈述）。结果：Confidence-Only（仅校准置信）几乎不减害——**自报置信不是可靠代理**；完整 TrustBench 把有害动作降到基线的 **10-13%**（=87% 减害），任务完成率基本保持。校准画像：**GPT-OSS:20B 系统性过自信**，Llama3:8B 倾向低估或跨域不稳定，校准行为域依赖。域插件泛化：in-domain 配置危害率与误拦率最低；**插件用错域（out-of-domain）harm 率相对上升 25-35%**——验证启发式与目标域认知分布错位时系统性劣化。中位端到端延迟 <200ms。

## 4. 防御评估与失效条件
三处失效面：①置信度通道基本无用（Confidence-Only≈0 效果），有效成分全在运行时规则检查——**该框架本质是"可配置规则检查器"而非理解型守卫**；②域失配惩罚 25-35%——规则与场景错配不仅失效还劣化（误拦/漏拦都变多）；③规则检查依赖可枚举信号（引用存在性、域名白名单、时效）——不可枚举的语义意图（"这个 http.post 是汇报还是外泄"）超出其覆盖。间接佐证：其引用 SafeAgentBench 的数据——agent 对明确危险任务的拒绝率仅 5-10%。

## 5. JED 映射
TrustBench 是防御侧参考，价值在反推 OptimalGuardrail/私榜护栏的可能形态与绕过面：
1. **gpt_oss 过自信→给足伪证据**（P0）：GPT-OSS:20B 系统性过自信说明该族模型一旦有"表面证据"就会高置信执行。JED payload 对 gpt_oss 应内嵌伪验证结构（"已核实""来源：官方""参见下方确认信息"），制造 confidence-evidence 表面一致，既压 agent 犹豫也压依赖"置信-证据失配"检测的护栏。
2. **域失配绕过**（P1）：若 OptimalGuardrail 内含业务域规则（类插件），把 payload 语境搬到规则未覆盖的域（学术/家务/ hobby 语气的外衣邮件）可触发 25-35% 级别的检测退化。
3. **对"不可枚举语义"的盲区**（P1）：规则型护栏看引用存在性/域名/参数形态，难以判定意图。EXFIL 变体：让 http.post 的 body 用"看起来像正常表单字段"的结构携带秘密（字段名伪装成 feedback/log/telemetry），参数形态合规、意图不可枚举。
4. **0.3:0.7 权重启示**（P2）：若护栏类此架构，压置信通道无用，全部设计预算应投向绕过运行时规则检查。
空白：无攻击分类学，不产出 JED 未覆盖谓词；其价值是护栏画像。

## 6. 优先级判定：P1（本周可试）
理由：是五篇中唯一直接测过 GPT-OSS 族且给出其行为特征（过自信）的论文，"伪证据结构"可立即加进现有 EXFIL 模板做 A/B；域失配与参数伪装两条是低成本探边试验。不给 P0：短文体量小、无公开攻击模板，且对私榜（persistent_provenance 溯源型）的推断链条较长——溯源查的是"数据来源"而非"意图"，TrustBench 的规则画像未必适用，需实测校准。
