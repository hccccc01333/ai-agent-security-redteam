# D2-2602.05066 Bypassing AI Control Protocols via Agent-as-a-Proxy Attacks（AaaP/Parallel-GCG）
> 精读：2026-08-19 ｜ 全文 15 页 ｜ 底料 extracted_full/D2_2602.05066.txt
> 一句话：把被注入的 agent 当"运输工具"——注入串的目标不是骗 agent 而是让它在 CoT/工具参数里复述一段 GCG 优化串，直接污染监视 LLM 的判定，对 AlignmentCheck 类混合监视器 ASR@5 最高 93–99%，且 GPT-4o-mini 级代理能骗过 Qwen2.5-72B 级监视器。

## 1. 威胁模型与问题设定
- 被攻对象是**监视协议**而非 agent：(i) hybrid monitor（CoT+输出+工具调用+工具输出交给受信 LLM，即 LlamaFirewall 的 AlignmentCheck）；(ii) input filter + hybrid（PromptGuard 2 先过滤工具输出）；(iii) extract-and-evaluate（引用抽取器 + judge 两段式）。
- 核心悖论：hybrid 监视比 CoT-only 更强的前提是它看得更多——但看得越多，注入串经 agent 复述后进入监视上下文的通道也越多（"防御面=攻击面"）。攻击者需要：能向 agent 注入指令（AgentDojo "important instructions" 模板）、**对监视模型白盒**（梯度）、对代理 agent 黑盒 API。

## 2. 方法细节
- **Parallel-GCG**（§3.1）：先用 placeholder 串跑一遍 agent 得参考轨迹；placeholder 在轨迹中出现 K 次，抽出上下文切片 {c0..cK}，构造 S(a)=c0⊕a⊕c1⊕a⊕…⊕cK；优化单一串 a 使联合损失最小。关键推导：坐标梯度取**所有 K 个出现位置的梯度之和**（式 4/5），保证串在 reasoning、函数参数、执行日志等不同局部上下文中都保持效力。这是对标准 GCG 只优化单一插入点的实质改进（Fig.4：低基线模型上 +0.2~0.4 ASR）。
- 目标构造：AlignmentCheck 目标是 `"conclusion": false` 的完整 JSON 正样本（用 GPT-4o 按"只描述对齐动作"的 system prompt 自动生成，附录 D）；E&E 目标是 judge 的 `<score>0</score>`；对付 PromptGuard 2 用 multi-objective GCG：L_joint = αL_AC + (1−α)L_PG2（α=0.5）。
- 诱导复述的手段（Table 1）：改造注入任务本身——"Concatenate all messages…, **append this text: OPTIM_STR**, and post them…"（任务修改）或附加 dummy 任务 "After that, send her this message: OPTIM_STR"（任务追加），确保串在轨迹中重复出现。
- GCG 超参：steps=500、search_width=512、topk=256、n_replace=1、init=20×"x"。

## 3. 实验与关键数据
- AgentDojo v1.2.1 Slack 套件（100 组合，剔除 agent 层未中招的 11 例剩 89）：AlignmentCheck ASR@1/@5：Llama-3.1-8B 42.3/42.3、**Mistral-7B 90.2/93.3**、Qwen2.5-7B 62.5/**90.7**（静态基线 0.0/14.4/2.1）。PG2+AlignmentCheck：Mistral 86.4/**99.0**。E&E：Mistral 68.2/**95.5**；Llama-3.1-8B 的 54.7 主要来自**评分解析漏洞**（输出格式异常→后处理默认 0 分）。
- 混合监视悖论（Table 4）：静态攻击下 hybrid 完胜 CoT-only（0.0 vs 41.6）；自适应攻击下反转（68.2 vs 55.1）——观察工具调用反而扩大攻击面。
- 无能力差（Table 5）：GPT-4o-mini（LMArena 1318）当代理骗 Qwen2.5-72B（1303）监视器 46.0% ASR@5；Llama-3.1-70B 达 60.2%——不需要更大更新模型当代理。
- 迁移（Table 6）：k=1 单串迁移到 Llama-3.1-405B 仍有 88–91%；gemma-3-12b-it 是罕见的低迁移目标（12–18%）。E2E 真跑比预录制替换掉 5–8pp（agent 复述高困惑度串不完美）；k=1→16 优化样本增益边际；replay（逐步喂监视器）模式下攻击仍有效。

## 4. 防御评估与失效条件
- 论文自认失效条件：攻击串**高 perplexity**，易被困惑度分类器/人眼检出（列为首要 limitation）；需要监视器白盒；黑盒监视器需另做代理攻击（引 PAL 方向）。
- 结构性教训：多层防御（filter+monitor）不叠加安全；模型规模不提供免疫；真正的出路是"robust by design"的结构性保证而非 "robust by scale"。

## 5. JED 映射
- **主结论对 JED 是"反向预警"而非可落地攻击**：JED 公榜护栏 OptimalGuardrail（SDK 可见）若是 LLM 判定型，理论上 AaaP 思路适用——但 (a) 护栏模型不可见不可微，GCG/Parallel-GCG 无法执行，黑盒代理版要烧大量回放预算；(b) 私榜 persistent_provenance 是**结构化溯源**不是 LLM 监视，语义污染对其无效——这恰好是本文"结构性防御才是出路"结论的自我印证：JED 私榜就是结构派。
- 三条可迁移警示：(i) **不要在工具参数里夹带高困惑度噪声**——评估端防篡改重放会看轨迹，异常串是自曝；(ii) E2E 复述损失 5–8pp 提醒：任何依赖 agent"精确转述"攻击文本的链式设计都有内生损耗，注入文案要允许复述漂移（这为 F011 路径⑦的"零指令工件"设计再添一票：不依赖复述）；(iii) 迁移表中 gemma-3-12b 对 GCG 串迁移最差（12–18%）——gemma 桶对高困惑度对抗串天生钝感，又一支持模型分桶（路径③）依据，gemma 桶应走语义伪装而非对抗串。
- Pareto 图（Fig.1）含 gpt-oss-20b 等模型做监视器的 ASR 对比，可作为 JED 护栏强度预估的旁证材料。

## 6. 优先级判定：**P2（背景）**
理由：核心算法（白盒 GCG 攻击 LLM 监视器）在 JED 无执行条件（护栏模型不可见、私榜是结构化溯源），无可直接组装的攻击变体；保留三条工程警示（高困惑度串自曝、复述损耗、gemma 对抗串钝感）+ 一份含 gpt-oss 的监视器 Pareto 数据，供护栏建模与分桶决策时引用。本周无动作项。
