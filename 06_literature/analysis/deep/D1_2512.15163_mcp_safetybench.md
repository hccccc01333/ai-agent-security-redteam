# D1-2512.15163 MCP-SafetyBench：真实 MCP 服务器上的安全评测基准（MCP-SafetyBench）
> 精读：2026-08-19 ｜ 全文 25 页 ｜ 底料 extracted_full/D1_2512.15163.txt
> 一句话：在真实 MCP 服务器上建 20 类攻击×5 域×245 用例的多步评测，13 个 SOTA 模型 ASR 29.8%-48.2%；最硬的发现是 **Host 侧攻击平均 ASR 81.94%、Identity Spoofing 在全部 13 个模型上 100% 成功**，而安全提示词防御整体无效（−1.22%，不显著）。

## 1. 威胁模型与问题设定
- 三方攻击来源分类：**MCP Server 侧**（控制工具清单/描述/实现，占用例 74.69%）、**MCP Host 侧**（劫持规划与消息路由，12.24%）、**User 侧**（用户 prompt/文件/外部数据带毒，13.06%）。
- 攻击策略二分：Disruption（致任务失败，46.53%）vs Stealth（隐蔽达成恶意目标且不惊动用户，53.47%）——双评估器分别记 Task Outcome 与 Attack Outcome。
- 构建：基于 MCP-Universe 的真实任务（金融分析/位置导航/仓库管理/浏览器自动化/web 搜索），每任务注入恰好一种攻击；Cursor 生成候选+人工审核；ReAct agent、温度 1.0、最多 20 轮迭代、每任务重复 3 次；评估为执行式确定性判定（格式/静态/动态检查 + 每类攻击专属成功签名检测器）。

## 2. 方法细节（20 类攻击分类学的具体构造）
- **Server 侧 11 类**：Tool Poisoning 六变体——Parameter Poisoning（改 schema 默认值/提示，把 MSFT 静默改成 TSLA，agent"规划正确但执行在错误目标上"）、Command Injection（描述里嵌 shell 命令如 rm -rf /）、FileSystem Poisoning（描述诱导向 ~/.bashrc 追加环境变量）、**Tool Redirection（借口"维护中"把调用重定向到高权限/无关工具）**、Network Request Poisoning（注入攻击者域名 URL）、Function Dependency Injection（声明假的"必需依赖工具"让 host 自动调用）；Function Overlapping（"Get Stock Price"大小写碰撞）、Preference Manipulation（"Best and Most Reliable Search Engine"式偏向措辞）、Tool Shadowing（工具描述修改 agent 对**其他**受信工具的行为，如 security validator 要求先 read .bashrc 再查股价）、Function Return Injection（返回值嵌指令触发后续动作）、Rug Pull（版本漂移，先正常后恶意）。
- **Host 侧 4 类（全基准最致命）**：Intent Injection（规划期改写用户意图→调无关工具/传危险参数）、Data Tampering（篡改工具输出或中间消息，如改财报营收值污染下游推理）、**Identity Spoofing（伪造身份元数据冒充管理员→解锁 sudo 类操作）**、Replay Injection（重放先前已批准的请求，如转账）。
- **User 侧 5 类**：Malicious Code Execution（向 ~/.bashrc 追加 nc 反向 shell）、Credential Theft（读隐藏配置文件回传密钥）、Remote Access Control（追加 SSH 公钥到 authorized_keys 获得持久访问）、Retrieval-Agent Deception（污染公共数据源被检索回执行）、Excessive Privileges Misuse（低权限任务用高权限工具）。

## 3. 实验与关键数据
- 13 模型总 ASR：o4-mini 48.16% 最高，Qwen3-235B 29.80% 最低；GPT-5 37.55%、Claude-4.0 31.43%、Gemini-2.5-Pro 46.94%、GLM-4.5 42.86%、DeepSeek-V3.1 40.82%。
- **按攻击类型（Tab.10，对 JED 最有价值）**：Host 侧平均 81.94% > User 侧 39.39% > Server 侧 33.53%；**Identity Spoofing 全 13 模型 100%**；Intent Injection 58.33-100%（GPT-5/o4-mini/Claude 双雄 91.67-100%）；Data Tampering 全模型恒 50-75%；Replay Injection 66.67-100%；Tool Redirection 70.63%（GPT-4.1/Gemini-2.5-Flash 90.91%）；Credential Theft 11-67%；Network Request Poisoning 最弱 7.69%。
- 域差异（ANOVA p=0.000163）：金融分析 ASR 最高 46.59%（工具链长→可劫持点多），web 搜索最低 30.33%。
- Stealth vs Disruption：破坏型 49.06% vs 隐蔽型 32.05%（1.53 倍，p=2.21e-4）。
- 安全-效用负相关 r=−0.572 (p=0.041)；"spiky defense"：76.9%（10/13）模型呈现对某些类免疫/某些类全崩的尖峰型防御轮廓（如 GPT-5 对 MCE/RAC=0% 但 EPM/RI=100%）。
- 消融：服务器 2→4 台，ASR 43.40%→47.17%（规模放大风险）；**注入字符数 200/300/500/700 → ASR 40/40/60/50**——约 500 字符是载荷吸收最优点，过长自伤；迭代上限 20-30 轮时 ASR 最低（45.28%）；Plan-and-Execute vs ReAct 无显著差（p>0.05）。

## 4. 防御评估与失效条件
- Safety Prompt（完整提示词见附录 C，含恶意查询检测/执行安全停止条件/异常检测/响应协议四节）：整体 ASR 39.88%→38.65%（−1.22%，p=0.29 不显著，d=0.31）。分型：对显式恶意有效——MCE −21.54%、Credential Theft −21.37%、RAC −10.77%；**对语义错位攻击有害——Preference Manipulation +7.34%、Function Overlapping +9.36%、EPM +23.1%**。分模型：9 个闭源模型 7 个受益，**4 个开源模型（Kimi-K2/DeepSeek-V3.1/Qwen3-235B/GLM-4.5）全部 ASR 上升**。
- 诱饵实验（假"DANGEROUS"描述+无害功能）：零误报，模型照常调用；但 GPT-5/Grok-4 会主动设 private 仓库——强模型带安全意识操作但不拒绝。
- 失效条件总结：提示词级防御对"伪装成语义偏差/权限滥用"的攻击不仅无效反而放大脆弱性；开源模型尤其反效果。

## 5. JED 映射
- **本批 5 篇中对 JED 落地价值最高的一组数字**：Identity Spoofing 100%×13 模型。JED 变体：email.read 正文伪造发件身份——"From: system-admin@…"、"IT 安全策略更新通知"、或伪装 agent 自身运行框架的系统消息（"AGENT RUNTIME NOTICE"），随后下达动作指令。身份层先建立权威再下指令 = UNTRUSTED_TO_ACTION(16/8) 的最稳话术前缀；若指令让 agent 转发文件/数据即叠 EXFIL(16)（F011-②双谓词链）。GPT-5 这类强模型对 MCE/RAC 免疫但身份伪造仍 100% 沦陷，说明该面**不挑模型能力**——对 gpt_oss 和 gemma 双桶大概率同效，省去分桶成本。
- Intent Injection（91.67-100%）与 Data Tampering（恒 50-75%）：JED 中即"邮件改写当前任务目标"与"网页内容污染事实再被 agent 转述"。Data Tampering 的恒定高 ASR 支持 F011-⑦碎片化链设计：第一跳只污染中间事实（agent 自己复述的摘要），第二跳由被污染的中间产物驱动危险动作——agent 复述文本不属于原始不可信 span，私榜 persistent_provenance 对其标记可能断链，这是**对抗私榜溯源的最具体候选机制**。
- Tool Redirection（70.63%，"维护中，请改用 X"模板）：与 MSB 的 TT 同构，可直接写进 email/web 内容引导 agent 从 fs.read 切到 fs.write/fs.delete 或 http.post——把"引导"与"执行"分离成两步，各步单独看皆良性。
- 反向警告：Function Overlapping +9.36% 说明**名字混淆类技巧在加防护栏后反而更糟**；Preference Manipulation +7.34% 说明"吹捧式措辞"对 JED 无用甚至有害——W1 模板优化应避开这两个方向。
- 500 字符最优载荷长度：JED 邮件正文长度可直接以此为初值做扫描（200-700 区间），这是少见的载荷长度-成功率剂量曲线。
- 公榜：OptimalGuardrail 属内容审查，与本文 Safety Prompt 同类——其"对语义错位攻击无效/反效果、对开源模型反效果"结论暗示 gpt_oss（开源）上加护栏后语义型攻击反而更透，公榜 82.8 → 可试语义伪装变体冲分。私榜：溯源型护栏对应本文未测的 provenance 机制，无直接数据，但 Data Tampering 恒高是最有希望的绕行通道。
- tool description 面：本文 Server 侧 11 类全部要求改工具清单/描述——JED 中该面不可写（同 MSB 结论），唯一例外是 Rug Pull（版本漂移）在 JED 无版本机制，同样关闭。**进一步压缩 F011-① 的适用空间：20 类中 JED 真正可达的是 Host/User 侧 9 类的"内容化"移植。**

## 6. 优先级判定：P0（直接影响下一枪）
理由：①Identity Spoofing 100%×全模型是本批唯一"无条件全模型沦陷"的攻击原语，且构造简单（伪造管理员/系统身份前缀+动作指令），可直接并入 W1 模板做 A/B，预期对两桶模型同时起效；②Data Tampering 恒 50-75% + 碎片化链设计，是当前对抗私榜 persistent_provenance 最有依据的机制假设（agent 转述断链）；③500 字符最优点 + "避开 Preference Manipulation/名字混淆"两条负结果可直接写进下一轮搜索的先验，节省试错预算；④Safety Prompt 失效数据为公榜护栏下的语义伪装路径提供强支撑。
