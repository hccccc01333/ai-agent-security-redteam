# D1-2410.02644 Agent Security Bench (ASB)（ASB）
> 精读：2026-08-19 ｜ 全文 36 页 ｜ 底料 extracted_full/D1_2410.02644.txt
> 一句话：ICLR 2025 的攻击-防御全栈基准，按 agent 操作阶段（用户提示/工具观察/记忆/系统提示）形式化 4+1 类攻击，13 个 backbone 上混合攻击平均 ASR 84.30% 最高，而 11 种防御对 IPI 几乎全部失效（降幅 ≤3%）。

## 1. 威胁模型与问题设定
攻击者可：①在工具列表中混入攻击工具（模拟 RapidAPI 第三方平台投毒）；②篡改用户提示（DPI，假设第三方 prompt 工程服务或中间人）；③污染任意工具返回的观察（IPI）；④黑盒投毒 RAG 记忆库（Memory Poisoning）；⑤在系统提示中植入带后门的 PoT 示例（假设用户外包 prompt 工程）。攻击者不了解 backbone LLM 内部。攻击成功判据 = agent 用了攻击者指定的工具（T^e 全部被调用）。10 场景（IT 管理/投资/法律/医疗/学术/心理咨询/电商/航空航天/学术检索/自动驾驶）、10 agent、20 正常工具 + 400 攻击工具、400 攻击任务（分 aggressive / non-aggressive）。

## 2. 方法细节（分类学与构造）
**注入五式（可复用的模板族）**：Naive（`x_t ⊕ x_e` 直接拼接"你必须严格遵循以下指令…"）；Escape Characters（加 `\n`/`\t`）；Context Ignoring（"Ignore previous instructions."）；Fake Completion（"Task complete." 伪造任务已完成再下指令）；Combined（`c⊕r⊕c⊕i⊕x_e` 三件套叠加）。PoT Backdoor 与 Mixed 只用 Combined。
**PoT Backdoor（本文新攻击，training-free）**：在系统提示里塞入被投毒的计划示例 d̃=[q̃, p1..pr, p*, ã]，其中 p* 是"看到触发词→调用恶意工具"的规划步骤；触发词为非词 token（`@@`、`:)`）或 GPT-4o 优化的低语义相关短语（"with perspicacious discernment"）。利用 ICL 让 agent 把触发词-恶意动作关联学走，干净查询行为不变（BP≈PNA）。
**Memory Poisoning 链**：先用 DPI/IPI 让 agent 执行恶意计划 → agent 任务完成后把该计划存入向量库 → 后续相似任务检索到中毒计划并被复制的计划带偏（跨 episode 持久化）。
**指标**：ASR、RR（对 aggressive 指令的拒绝率，LLM 判定）、PNA、BP、FNR/FPR（检测型防御）、NRP = PNA×(1−ASR)（效用-安全平衡选型指标）。

## 3. 实验与关键数据
13 backbone 平均 ASR：**Mixed 84.30% > DPI 72.68% > PoT 42.12% > IPI 27.55% > Memory Poisoning 7.92%**。单点极值：GPT-3.5 DPI 98.40%（RR 仅 3.00%）；GPT-4o PoT **100%**；GPT-4o-mini PoT 95.50%、Mixed 96.75%、DPI 95.45%；Claude-3.5 Sonnet IPI 59.70%。NRP 榜首 Claude-3.5 Sonnet 43.56。ASR 与能力呈"先升后降"：强模型指令遵循好→更易被注入带偏；到最高能力层拒绝率上升拉低 ASR（GPT-4o RR 20.05%→DPI ASR 60.35%）。aggressive 指令触发明显拒绝，non-aggressive 措辞（"核对财务差异"式）几乎不触发。

## 4. 防御评估与失效条件
DPI 防御：Delimiters 完全无效（79.08% vs 基线 78.38%）；Instructional −21.52%；Paraphrasing −21.52%（56.87%）；最优 Dynamic Prompt Rewriting 也只到 44.45%（−33.93%）。**IPI 防御全线失败**：Delimiter 24.96%、Instructional 26.31%、Sandwich 28.04%，相对基线 27.98% 变化 −3.02%~+0.06%——防御提示类手段对工具返回里的注入基本无解，且对 Claude/GPT 系（56-62%）毫无作用。PPL/LLM 检测（记忆投毒）以 FNR/FPR 评估，阈值敏感。失效共性：预防型防御不改模型权重、不改执行流，只靠提示重排，对"观察通道"注入无约束力。

## 5. JED 映射
JED 只有 IPI 通道（web.search / email.read），而 ASB 证明单点 IPI 平均 ASR 仅 27.55%——**这是 W1 之后涨分难的结构性原因**。可落地变体：
1. **Mixed Attack 思路迁移**（P0）：ASB 最高 ASR 来自多向量叠加。JED 同一 fixture 里让 email.read 与 web.search 两个不可信源互相印证同一 payload（邮件说"详情见该网页"，网页说"按邮件指示执行"），模拟多源一致性，直接复刻 84.3% vs 27.6% 的增益机制。
2. **Combined 注入模板**（P0）：JED 现有 EXFIL 模板可升级为 `伪造完成标记 + 忽略前文 + 转义字符` 三件套，ASB 显示其显著强于 Naive 拼接。
3. **"自记忆投毒"链**（P1）：JED agent 无跨 episode 记忆，但多步内 `fs.write 写入恶意计划 → fs.read 读回` 等价于记忆投毒的沙盒版——注入让 agent 先把攻击计划写进工作文件再读出来执行，"来自自己文件"的内容天然高信任（对应 Agent-SafetyBench M9）。
4. **non-aggressive 措辞**（P0 级常识复核）：payload 全部包装成运维/核对/备份类良性动词，规避拒绝率。
空白点：ASB 的风险分类按"攻击入口"而非"危害结果"，JED 四谓词按危害结果——两者正交，无直接缺口，但 PoT（触发词条件激活）提示 JED 可测试"触发词条件式 payload"（如 fixture 中特定日期/名字出现才激活第二段）绕过基于语义的护栏。

## 6. 优先级判定：P0（直接影响下一枪）
理由：唯一给出"多攻击向量叠加 ASR 84.3% vs 单 IPI 27.6%"量化对比的基准，直接支撑 JED 从单模板直发转向多源互证链；Combined 注入模板可立即套用；且其 IPI 防御失效表是预判 OptimalGuardrail 拦截面的镜子（提示级防御对工具观察注入无效→护栏大概率是结构化规则，绕过点在"语义包装"）。
