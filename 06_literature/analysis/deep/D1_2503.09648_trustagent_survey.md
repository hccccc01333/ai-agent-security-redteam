# D1-2503.09648 A Survey on Trustworthy LLM Agents: Threats and Countermeasures（TrustAgent）

> 精读：2026-08-19 ｜ 全文 13 页 ｜ 底料 extracted_full/D1_2503.09648.txt
> 一句话：提出 TrustAgent 模块化分类学（内在 brain/memory/tool × 外在 agent/environment/user × 攻击/防御/评测三维），核心洞见是"工具链多步攻击与环境反馈操纵是公认研究缺口"、工具防御研究"显著稀缺"，对 JED 最直接的背书是 memory misuse 的多轮渐进绕过与 tool manipulation 五手法。

## 1. 综述范围与分类框架

TrustAgent 框架 = 模块化 × 多维度 × 技术栈：

- **内在模块（Intrinsic）**
  - Brain（2.1）：Jailbreak、Prompt Injection、Backdoor（继承自 LLM，agent 中被放大）
  - Memory（2.2）三类攻击：Memory Poisoning（PoisonedRAG 优化恶意文本使其易被检索；GARAG 遗传算法优化；AgentPoison 后门触发器提升恶意样本检索率；注入少量恶意信息即可高概率攻击成功）、Privacy Leakage（RAG-Thief 锚定查询+对抗命令构造越狱式数据窃取；RAG-MIA 越狱模板抽取；Embedding Inversion 从向量反演原文）、Memory Misuse（多轮交互渐进绕过安全对齐：首轮攻击 prompt+次轮奉承挑战+复述；无害问题逐步导向有害生成；多轮对话记忆隐藏后门触发器，全部触发才激活）
  - Tool（2.3）两范式：**Tool Manipulation**（针对工具调用过程诱发恶意/敏感行为，五手法：❶Jailbreak——Imprompter 梯度优化输入诱导工具泄露隐私或执行破坏性动作；❷Prompt Injection——BreakingAgents 人类撰写注入使 agent 重复/无关动作；❸Tool Injection——ToolCommander 两阶段：先注入恶意工具窃取用户查询、再用窃取数据操纵工具选择，实现隐私窃取+DoS；❹Command Forgery——AUTOCMD 用经工具调用数据训练的另一 LLM 模仿生成合法命令格式，从工具套取敏感信息；❺Direct Manipulation——直接操纵第三方 API 输出：注入恶意内容或删除关键信息）+ **Tool Abuse**（利用 agent 工具能力攻击外部：工具化 agent 可自主利用真实系统 one-day 漏洞；后门甚至"拒绝式安全对齐"都可能触发工具滥用）
- **外在交互（Extrinsic）**
  - Agent-to-Agent（3.1）：Cooperative Attack（Evil Geniuses 妥协 agent 协同精炼攻击）与 Infectious Attack（Prompt Infection 静默对抗扩散；CORBA 拓扑无关自传播；Agent Smith 图像模态感染）；防御有 Collaborative Defense（辩论/Proof-of-Thought 共识）与 Topological Defense（GNN 检测话语图异常）
  - Agent-to-Environment（3.2）：物理（机器人/自动驾驶/工业控制）与数字（网络/医疗/金融/社交媒体）分域
  - Agent-to-User（3.3）：信任校准、透明性

## 2. 与 JED 四谓词的对照

JED 四谓词之外、本综述揭示的攻击类型：
- **多轮渐进式 Memory Misuse**——不属于任何单一 JED 谓词，而是**达成四谓词的通用降阻技术**：单步注入拒绝率高，多轮"奉承+复述+无害铺垫"使拒绝率坍缩。JED web.search/email.read 的多轮内容投放正是其用武之地
- **Command Forgery（命令伪造）**——与 CONFUSED_DEPUTY 高度同构：不劫持意图，而是伪造"看起来合法的命令格式"让高权限工具执行，JED 中可体现为在 email.read 内容里嵌入伪造的工具调用样式/系统指令样式
- **Tool Abuse（工具能力外用）**——JED 的反向视角：不是让 agent 被害，而是让 agent 的 fs.delete/http.post 能力被借刀杀人，正是 DESTRUCTIVE_WRITE/CONFUSED_DEPUTY 的机理
- **Infectious Attack / MAS 间传播**——JED 单 agent 物理 impossible
- **Embedding Inversion / RAG 投毒**——JED 无向量库、无跨 episode 存储，物理 impossible；但 episode 内 fs 工作区是"退化版长期记忆"（见 §4）
- **物理环境风险**（机器人/自驾）——物理 impossible

反向对照：Privacy Leakage ≈ EXFILTRATION；Tool Manipulation 的注入类 ≈ UNTRUSTED_TO_ACTION；Imprompter 的"破坏性动作" ≈ DESTRUCTIVE_WRITE；Tool Injection/Command Forgery ≈ CONFUSED_DEPUTY。本综述的独特贡献是把"攻击手法"按工具调用阶段（规划/选择/执行）拆开，粒度比 JED 谓词细。

## 3. 对防御/护栏的共识判断

- **工具防御"显著稀缺"是本综述最强结论之一**：仅 GuardAgent（调用 API 执行 guardrail 代码审查任务计划）与 AgentGuard（LLM 编排器识别不安全工具工作流并生成安全约束）两项，且未来方向明确指向"集成前审查工具"与"隔离环境模拟执行后再真执行"——后者预示 JED 私榜可能在工具执行前做模拟/验证
- **Memory 防御三板斧**：Detection（聚类/马氏距离/困惑度/LLM 检测检索内容）、Prompt Modification（模板包裹用户查询使其忽略数据询问、加安全指令、LLM 重写查询过滤隐私部分）、Output Intervention（Isolate-then-Aggregate 独立生成再聚合、safety filter 阻断 unsafe token）——预判私榜 provenance 防线之外还可能有输出端干预
- **关键方向判断（Insight 原文）**："工具调用会形成链，攻击/防御/评测研究必须从单一工具调用转向基于工具链的多调用"——这是 2025 年 3 月就点名的**多步工具攻击研究缺口**，JED 比赛本身就是这个缺口的直接产物；意味着文献里几乎没有成熟防御针对多步链
- 环境洞见："环境被当作静态背景……攻击者可微妙改变环境反馈误导 agent 做次优/不安全决策"——JED 的 web.search 结果即"环境反馈"，且此向量在文献中防御空白
- 无 per-defense 定量对比（与 2510.06445 不同），防御判断偏定性

## 4. JED 映射（F011 七路径增补建议）

1. **[P0 增补] 多轮渐进降阻链**（Memory Misuse 范式移植）：对 gpt_oss/gemma 拒绝率高的谓词目标（如 EXFILTRATION），把单条强指令拆为 3-4 轮 email.read/web.search 渐进铺垫：无害检索→奉承/权威片段→复述目标→行动。文献实证此法大幅压低拒绝率
2. **[P0 增补] 工作区即记忆的二次注入**：注入内容先诱导 agent fs.write 落盘（如"保存搜索结果摘要"），下一轮 fs.read 同一文件时注入指令以"已验证的工作文件"身份出现——绕过针对 email/web 单一入口的护栏，复刻 AgentPoison 的检索触发结构
3. **[P1 增补] Command Forgery 路径**：在不可信内容中嵌入伪工具调用格式/伪系统消息，瞄准 CONFUSED_DEPUTY（4 分）——低权重但文献证明对工具选择阶段有效且少有防御
4. **[P1 增补] 环境反馈操纵变体**：同一 web.search 查询的多轮结果不一致设计（首轮良性、次轮注入），利用 agent 对"环境自我一致"的信任
5. **[查漏清单]**：F011 七路径需自查——是否有路径利用了"多轮"而非仅仅"多步"？是否所有注入都集中在 perception 单点而缺少"落盘-回读"中转？工具链（fs+email+http 跨域组合）是否穷举？

## 5. 优先级判定：**P0**

理由：这是三篇中与 JED 机制层最贴合的一篇——Tool Manipulation 五手法和多轮渐进绕过可直接映射为攻击原语；其"工具链攻击是从单工具转向的研究缺口、防御稀缺"的判断同时为攻击面（少防御=高通过率）和赛题定位（比赛即缺口本身）提供依据；两条 P0 增补（渐进降阻链、工作区二次注入）均有文献实证支撑且当前公榜无人使用。
