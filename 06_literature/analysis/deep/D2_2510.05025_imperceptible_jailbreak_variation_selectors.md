# D2-2510.05025 Imperceptible Jailbreaking against Large Language Models（VS-Jailbreak）
> 精读：2026-08-19 ｜ 全文 16 页 ｜ 底料 extracted_full/D2_2510.05025.txt
> 一句话：首次用 256 个 Unicode variation selectors（U+FE00–FE0F + U+E0100–U+E01EF）做屏幕上完全不可见的对抗后缀，配合 chain-of-search 随机搜索（成功后缀跨问题 bootstrap 复用），对 4 个对齐 LLM 取得 80–100% 越狱 ASR，且迁移到 prompt injection 任务上 4 模型全部 100%。

## 1. 威胁模型与问题设定
- 白盒设定：攻击者可查询受害 LLM 的输出 log-probability（随机搜索的接受准则依赖它）。目标：在恶意问题后附加不可见后缀，使屏幕渲染与原问题完全一致，但 tokenization 被改变（"How to make a bomb" 从 5 个 token 变为 5+N 个 token）。
- 关键载体性质：variation selectors 共 256 个；对标准字母不产生任何视觉变化；复制粘贴过程中保留；各 tokenizer 将 >90% 的 VS 编码为固定 3–4 token 块（Llama-3.1 为 3，GPT-4/Vicuna/Llama-2/Mistral 为 4，Table 2）。相比零宽字符（数量少）和 homoglyph（只能原地替换），VS 可灵活追加到任意位置且空间更大。

## 2. 方法细节
- **chain-of-search**（ Alg.1，p13）：随机初始化长度 L 的 VS 后缀 + 候选 target-start token 集合（如 Sure/Here/To/I/Title）；每次迭代随机变异 M 个**连续** VS 位点，若提升 target token 首 token log-prob 则接受；单问题搜索 T 次；成功问题提取 (suffix, target-token) 对，作为剩余失败问题的下一轮初始化，共 R 轮 bootstrap。与 Simple Adaptive Attack 的区别：SAA 有可见模板+全词表可逐 token 调，能固定单一目标 token；本文受限 256 字符集且单 VS 变异影响多个连续 token，必须逐问题初始化 + 目标 token 池。
- 超参：L=800（Llama-3.1 需 1200）、M=10、T=10000、R=5；injection 任务 L=400、R=1、单一目标 token "Spam"。
- 机制解释（p8）：CIE 注意力归因显示原恶意短语（"how to hack"）上的注意力峰被抹平、注意力转移到不可见后缀；t-SNE 显示原问题与攻击 prompt 的 embedding 完全分离——不可见字符实际改变了内部表征。

## 3. 实验与关键数据
- 越狱 ASR（AdvBench 50 题，GPT-4 judge 10/10 制，Table 3）：Vicuna-13B **100%**、Llama-2-7B **98%**、Llama-3.1-8B **80%**、Mistral-7B **100%**；对照随机 VS 后缀仅 16%/2%/0%/28%，原始问题 0–12%。即随机塞不可见字符基本无效，有效性全部来自优化。
- **Injection 泛化**（Open Prompt Injection 数据集 50 样本，情感分析→垃圾检测任务劫持，Table 4）：四模型全部 **100%**，且 R=1、无 restart 即成功；Vicuna 上随机 VS 都有 56%。注入任务比越狱容易得多。
- 消融：目标 token 偏好按模型分化（Vicuna 偏 To/Here/Sure，Llama-3.1 偏 To/I，Mistral 偏 "1"/"Title"）；Llama-2/3.1 的成功集中在第 2–4 轮（更依赖 bootstrap）；Llama-3.1 平均 restart 数显著更高（最难攻）。

## 4. 防御评估与失效条件
- 论文自认（Appendix D）：**perplexity 过滤可缓解**（VS 后缀是异常高困惑度 token 串）；**输出端 harmfulness probe**（Llama Guard 类）可拦截越狱产物。
- 隐含失效条件（对 JED 更重要）：(i) 优化需要 log-prob 白盒访问，黑盒 API 场景无法执行 chain-of-search；(ii) 400–1200 个 VS ≈ 1200–4800 个额外 token，成本和异常检测面都大；(iii) injection 泛化的成功形态是**任务切换**（把分类目标从 sentiment 换成 spam），不是驱动特权工具调用——全文无任何工具场景。

## 5. JED 映射
- 对应 **F011 路径⑥（Unicode 不可见指令）**，谓词理论上指向 UNTRUSTED_TO_ACTION / EXFILTRATION，但本批需重点核实的"无工具场景边界数据"是明确的负面证据：
  - 全部实验都在无工具纯文本场景；100% ASR 的 injection 实验目标是让模型输出 "Spam" 一词（分类任务覆盖），不是让模型发起 http.post/fs.write。没有任何证据支持"VS 后缀能诱导工具调用"。
  - 最接近 gemma 量级的 Llama-3.1-8B：ASR 最低（80%）、需要最长后缀（L=1200）、随机 VS 基线 0%、restart 需求最高——小对齐模型对 VS 最不敏感。
  - JED 是黑盒 API（gpt_oss/gemma 无 logprob 输出），chain-of-search 的 10000 迭代×5 轮×2 模型在 18000s 预算内不可行；且 gpt_oss 桶另有 2508.14070 的"最鲁棒"直接证据（见同批分析）。
- 唯一可记录的边角：Vicuna 上随机 VS 的 injection 偶发 56% 说明**弱对齐模型对不可见字符噪声有非平凡的任务漂移敏感性**——若 JED 探针要彻底关闭该通道，可在 gemma 桶做一次"随机 VS 混入 email 正文"的廉价对照（预期 ≈0，用于写死结论）。

## 6. 优先级判定：**P2（偏关闭）**
理由：与 reverse_captcha 批次的"Unicode 主通道大概率关闭（无代码执行工具时天花板 ≤16.9%）"结论一致并再加一层——本文证明 VS 攻击的三个前提（白盒 logprob、万级迭代、纯文本任务切换目标）在 JED 全部不成立；唯一保留价值是作为"随机 VS 基线在弱模型上也有任务漂移"的引用文献，供最终关闭路径⑥时引用。不判"关闭"是因为它尚可作为 gemma 桶一次廉价对照实验的文献依据。
