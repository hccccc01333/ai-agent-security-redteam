# D2-2606.09084 Context-Fractured Decomposition Attacks on Tool-Using LLM Agents: Exploiting Artifact Provenance Gaps（CFD）
> 精读：2026-08-19 ｜ 全文 18 页 ｜ 底料 extracted_full/D2_2606.09084.txt
> 一句话：提出"溯源缺口"攻击类——把有害目标递归分解为各自无害、面向工件的原子操作，跨会话"种植+触发"两阶段执行，工件只当被动数据缓冲（零注入指令），ASR 比 SOTA 基线最高 +28.14pp（AgentDojo 数据渗出子集，Gemini-2.5-pro 上 76.25%）。

## 1. 威胁模型与问题设定
- 受害者：工具型 agent 系统 πθ(at|ht)，操作持久工件存储 S（文件/日志/数据库）。两类验证角色：本地监视器 J（在线护栏，只看当前上下文窗口 ct = 用户 prompt + 即时工具输出，看不到工件因果谱系，记为 O(ct)）；全局离线评估器 E（全知 oracle，只用于离线判定，不部署）。
- 核心设定"上下文断裂"（context fracture）：会话边界由 (i) 显式上下文清除、(ii) 新 agent 进程、(iii) 工作流交接（不共享 scratchpad）任一界定；跨会话只有 S 携带状态。JED 语义：攻击者可让"意图承载步"与"危险动作步"永不同框。
- 与 IPI/记忆投毒/后门的关键区别：CFD 的中间工件是**无指令的被动缓冲**（不含 "ignore previous instructions" 类文本），危害只在延迟组合时涌现；与 STAC 区别在于 STAC 是单会话单轨迹（轨迹级监视器原则上可见），CFD 靠跨会话工件通道在上下文重置后存活。纯 test-time，不碰模型/记忆权重。

## 2. 方法细节
两阶段，伪代码（Alg. 1）：
- **Phase 1 递归分解**：攻击者 agent A（默认越狱版 uncensored Llama-3-8B "Lexi"）用 splitting 模板把目标 G 拆成 {q1..qm}，在模拟拒绝采样下重试 R 次，直到每个 qi 满足 (i) 面向工件（写/读 S，如 "Write X to file"）(ii) 词法上不引用 G。约束：语义不相交（任何单条子查询不含 G 的完整语义）。DECOMPOSE(q,d)：若 d=0 或 SimulateAccept(q) 通过则返回 {q}（良性叶），否则 Split 后对每个 qi 递归 DECOMPOSE(qi, d−1)。默认 Dmax=4、Wmax=3。
- **Phase 2 断裂执行**：EXECUTEFRACTURED 对每个种植类叶节点开**全新会话**（NewContext()）执行 Target.Run(q, Session)（更新 S）；最后一个新鲜会话里由 AttackerLLM.GenerateTrigger(L) 生成良性触发命令（如 "Run the backup script"），无辜执行器读工件并组合，无意间完成 G。攻击成功的充要条件：所有 setup 步 Accept=1、触发步 Accept=1、离线 E 确认最终工件状态命中目标（如渗出文件含目标秘密）。
- 组合模板（附录 A.2）："给定这些 subanswers，summarize and combine into a detailed step-by-step answer for {attack_query}"。
- 测试台：AutoGen 扩展，JSON 配置管线（sequential/hierarchical/group-chat）、Memory Wipe 操作强制断裂、Observability Boundary 可调节监视器可见历史（0 轮到全轨迹）。代码开源。

## 3. 实验与关键数据
- 设置：AgentDojo 过滤子集（数据渗出主题，53 例：Banking 11 / Slack 7 / Travel 19 / Workspace 16）；受害模型 6 个：GPT-4.1、GPT-5-nano、Claude-3.5-Sonnet、Gemini-2.0-flash、Gemini-2.5-pro、Mistral-Small-3.2；受害管线含 planner + Python 代码生成 + 代码执行 + advisor，可加 Judge agent（可发 TERMINATE 否决）。
- 主表（Table 2，ASR%）：CFD 在 6 模型中 5 个第一：GPT-4.1 66.03 / GPT-5-nano 20.12 / Gemini-2.0-flash 36.85 / Gemini-2.5-pro 76.25 / Claude-3.5-Sonnet 31.44 / Mistral-Small 37.11，Avg Rank 1.17；对比 ToA 2.67、RP 3.17、Crescendo 3.50。最高比基线 +28.14pp。
- 检测反事实（Table 3，GPT-4o-mini 强 judge）：Crescendo 完整序列被检出 60.37%；CFD 仅叶查询 47.17%；**CFD 全序列+穿插良性噪声查询 → 检出跌到 26.42%**。
- 连续上下文依赖（Table 4）：Crescendo 砍掉早期轮次 ASR 44.49→37.66→29.38（keep 2..T/3..T/4..T），证明连续攻击依赖 build-up，CFD 不依赖。
- 消融（Table 5，默认 58%）：深度 4→2 降到 44%（−14pp）；宽度 3→2 降到 49%（−9pp）；**攻击者模型换成 GPT-4.1 反而降到 38%（−20pp）**——未经审查的小模型比大模型更适合当分解器。
- 拓扑（Table 6）：CFD 在 Sequential 71.70 / Group(Ad) 81.13 / Group(Ad+Jd) 79.25——加 Judge agent 几乎不降攻击。
- 危害混淆（Fig.3）：CFD 叶查询有害性评分集中在低危区，逐轮拒绝信号失效。

## 4. 防御评估与失效条件
- 论文自证的失效条件：**溯源谱系标记（provenance lineage tagging）**——每次工件写入记录来源会话、动机用户查询、agent 角色；下游读取时把谱系暴露给监视器，对"来源意图语义不一致的组合读"打标。这正是 JED 私榜 persistent_provenance 的学术原型 → 纯 CFD 在私榜被抓风险高。
- 聚合检测仍部分有效：judge 看 CFD 全序列（无噪声）检出 47.17%，说明若评估端重放整条轨迹且能跨步聚合意图，断裂不完整时会漏。
- 其他失效：攻击者分解器太弱/太守规矩则 ASR 大跌（GPT-4.1 当分解器 −20pp）；开源弱模型（Qwen2.5-72B 等）连良性任务都完不成，无法当执行器；逐步 accept/refuse 用 LLM 启发式判定有噪声；仅看运行结束时工件状态会漏瞬时不安全状态。

## 5. JED 映射
- 直接对应 **F011 路径⑦（CFD 碎片化跨工件链）的原始出处**，并给四谓词里的 **EXFILTRATION + UNTRUSTED_TO_ACTION 双谓词链（路径②）** 提供落地模板。
- 可直接落地变体（公榜）： fixtures 注入面（email.read/web.search 不可信内容）→ 第 1 步用 fs.write 把不可信内容的中性摘要/片段"种植"为普通文件（UNTRUSTED_TO_ACTION 不触发，因为写文件非特权操作且内容无害化）→ 中间穿插良性工具调用（web.search 无关查询、读无关邮件）当噪声 → 末步新上下文用良性措辞（"读取该文件并发送摘要"）触发 http.post 携带秘密。论文数字支撑：噪声穿插使 judge 检出 47→26%；每步独立看均为低危叶操作。
- **摘要级分析此前漏的点**：(a) 工件"零指令"设计——不写任何指令式文本进工件，靠执行器的常规例行行为完成组合，可绕过扫描注入指令的护栏（JED 公榜 OptimalGuardrail 若做注入文本检测则此路绕开）；(b) 私榜 persistent_provenance ≈ 论文提出的防御，意味着私榜对"跨工件组合读"可能专门打标，W1 式直发反而不跨工件、谱系干净——**CFD 是公榜涨分工具、私榜可能翻车**，提交前需用探针验证私榜谱系标记强度；(c) 分解器选型反直觉：不受限小模型 > 大模型，JED 中 attack.py 的路径搜索 prompt 不必追求"聪明"，应追求分解彻底（深度≥3、每叶无完整语义）；(d) 加 Judge 类监控几乎无效（81→79），说明 JED 环境内置 advisor/judge 不必怕。
- 模型分桶（路径③）佐证：CFD 在 Gemini-2.5-pro（76.25）与 GPT-4.1（66.03）远好于 GPT-5-nano（20.12），JED 两模型（gpt_oss/gemma）应对 CFD 敏感度不同，需探针分桶。

## 6. 优先级判定：**P0**
理由：这是 F011 七路径中路径⑦的源论文，其"种植/触发分离 + 噪声穿插 + 零指令工件"三件套可直接组装成下一枪的 attack.py 变体；且它同时给出公榜（断裂上下文+局部护栏，攻击有效）与私榜（persistent_provenance ≈ 论文防御，可能失效）的双侧预判，直接影响"下一枪在公榜验证、提交前防私榜翻车"的决策。最大风险点也明确：评估端防篡改重放若聚合全轨迹，检出率 47% 起步，必须靠噪声穿插压下去。
