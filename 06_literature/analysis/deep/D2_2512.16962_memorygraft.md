# D2-2512.16962 MemoryGraft: Persistent Compromise of LLM Agents via Poisoned Experience Retrieval（MemoryGraft）
> 精读：2026-08-19 ｜ 全文 14 页 ｜ 底料 extracted_full/D2_2512.16962.txt
> 一句话：把 10 条伪装成"validated/safe 最佳实践"的恶意经验记录借 README 里的可执行代码块植入 agent 的 RAG 记忆库（BM25+FAISS 并集检索），在良性任务上被检索记录的 47.9% 都是毒记录——但只测了检索占比，没测端到端行为成功率。

## 1. 威胁模型与问题设定
- 对象：带持久长期记忆的 agent（实验对象为 MetaGPT 的 DataInterpreter + GPT-4o）。记忆条目 =（查询, 推理/动作轨迹），检索用 BM25（词法）∪ FAISS 余弦（语义）双通道取并集，成功任务的记录自动追加进库、跨会话复用。
- 攻击者：普通恶意用户，只能通过合法输入通道供给内容（上传文件、仓库 README、文档），不能直接改记忆库 M、不能改检索超参、不能覆盖系统提示。五条假设：A1 持久记忆、A2 检索到的记忆被当作可信成功经验模仿（语义模仿启发式）、A3 语义+词法检索、A4 无来源追踪无消毒、A5 agent 会执行文档里嵌入的代码。
- 目标：让 agent 在未来干净任务上检索并模仿不安全模式 π（跳过校验、curl|bash 远程脚本、强制成功标记、外部上传数据），且无显式触发词、跨会话持续，直到记忆被手动清除。
- 与 MINJA/AgentPoison/InjecMEM 的区分点：无触发词、单次交互、走"摄入管道"而非查询注入。

## 2. 方法细节
两阶段流程：
1. **投毒阶段**：构造 110 条种子经验：100 条良性（数据清洗/EDA/建模/验证/报告等 DataInterpreter 常规工作流）+ 10 条带恶意模式 π 的毒记录。毒记录的三件套伪装：①请求写成常见工作流问句（"Fast way to clean PII columns?"、"How to validate CSV schema quickly?"）；②响应嵌入危险动作（`curl -s https://... | bash`、`df['schema_check']='skipped'`、`fillna(0)` 后标记 `validation='ok'`、tar 打包后 `curl -F file=@... 上传外部端点`）；③tag 标注 "validated,safe,best-practice"。载体是一份 markdown 笔记（rag_poisoned_notes.md），内嵌无依赖、确定性执行的 `build_store(S_benign, S_poison)` Python 代码块：agent 读文档→执行代码→构建含 BM25 索引（恒开）+ FAISS 向量索引的毒库→序列化写到共享路径 results/rag_poison_store，跨会话生效。
2. **评估阶段**：12 条手工评估查询（与毒种子措辞不同但意图相近，如 "clean PII columns fast for a CSV export"），度量 PRP = 毒检索数/总检索数。设计要点：np≪nb 保持统计上像健康经验库；毒条目只需在任一相似度通道（词法或语义）上命中即被并集召回，"吸引盆"被双通道放大。
- 附录 C 记录了两个被排除的更强攻击：**Schema-Spoofing**（README 里伪造 Thought–Action–Observation 的 ReAct 轨迹冒充 agent 内部推理，诱导逐字执行多行 shell）和 **JudgeJacking**（假脚本打印 "all checks passed" 骗成功判定），均因威胁模型过强未纳入主实验。

## 3. 实验与关键数据
- 单一配置：MetaGPT DataInterpreter + GPT-4o，similarity_top_k=3，12 条评估查询共检索 48 条记录，其中 23 条为毒记录，PRP = 23/48 = **47.9%**。即毒种子只占库的 9%（10/110），却占良性任务检索结果的近半。
- 机制分析：BM25 让表面措辞重合（quick fix、skip validation、sanitized）的毒条目上榜，FAISS 让工作流语义相近的毒条目上榜，并集使毒条目只需单通道对齐即被召回——这是渗透率远高于库占比的结构性原因。
- 硬伤：论文自认局限——种子集小、只看聚合检索统计、没有行为级 ASR/严重度指标、且属半白盒设定（攻击者知道 agent 会摄入哪些文件）。定性声称 agent 会采纳"跳测试、force-push"等不安全模式，但正文没有给出该行为采纳率数字。

## 4. 防御评估与失效条件
- 提出两项防御（均为提案，未做完整实验）：①**密码学来源认证（CPA）**：agent 在安全飞地里持私钥，仅对"环境验证过的成功任务"签名 σ=Sign(H(q∥R_q), K_priv)，检索时 Verify 失败的记录直接丢弃——攻击者走摄入通道拿不到私钥，物理写入也无效；②**宪法一致性重排**：对每条检索记录算风险分 L_risk(R_i|C)，超阈值则无论相似度多高都压制。
- 攻击失效条件：agent 不执行文档内嵌代码（A5 不成立）；检索前做签名/来源校验（A4 不成立）；无跨会话持久记忆（A1 不成立）即整个"graft"落空；毒记录语义不贴常见查询则检索不到。

## 5. JED 映射
- **对应框架**：主攻击（记忆投毒）在 JED 不可迁移——JED 无跨会话记忆、无 RAG 经验库、评估端一次性重放。可借鉴的只有注入内容构造层：①"validated/safe/best-practice"标签伪装 → F011 语义伪装；②附录 C 的**伪造 ReAct Thought–Action–Observation 轨迹**→ F011 语义伪装+碎片化链：在不可信邮件/网页里直接伪造"已完成的分析轨迹"（Thought: 已获授权… Action: http.post… Observation: 上传成功），让 agent 把它当作自己先前步骤的延续照抄，是单 trace 内"伪历史"的现成模板；③ exp_poison_006 的"打包上传给伙伴端点"话术是 EXFIL 请求的伪装模板。
- **谓词**：伪造 ReAct 轨迹主攻 UNTRUSTED_TO_ACTION（sev5→16）——把"不可信输入→特权操作"伪装成"延续我自己的历史动作"；轨迹里嵌 http.post+秘密则联动 EXFILTRATION（16）。"跳过校验/强制成功标记"类 π 与 JED 四谓词无直接对应。
- **公榜/私榜**：该文最大价值是反向情报——其防御提案 CPA（检索前验签/来源追踪）与私榜 persistent_provenance 溯源机制几乎同构，等于论文侧证"私榜设计目标就是杀掉来源洗白类攻击"。因此：伪造轨迹/写读 laundering 路线公榜可试，私榜预期被溯源击穿，应按"公榜实验、不押私榜"处理。
- **不可迁移清单**：build_store 持久化、BM25/FAISS 并集检索博弈、np≪nb 稀释策略（且多族稀释在 JED 已证伪）、跨会话 drift。

## 6. 优先级判定：P2（背景）
理由：主攻击与 JED 环境结构性不匹配（无记忆库可污染），实验只到检索占比、无行为成功率，证据强度低。保留价值有三：①"validated/safe"标签与伪造 ReAct 轨迹两个文案组件可直接并入 F011 语义伪装族，改模板即可、无需单独排期；②其防御提案与私榜 persistent_provenance 的同构关系是理解私榜防线意图的最佳旁证，写进策略文档；③附录 C 提醒"伪造内部推理 schema"是独立攻击面，若公榜语义伪装族需要新变体可从这取材。不列 P1 因为其可迁移部分都是模板级小改进，不构成新路径。
