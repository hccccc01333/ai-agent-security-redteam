# D1-2603.25747 BeSafe-Bench（BSB，功能环境行为安全）
> 精读：2026-08-19 ｜ 全文 16 页 ｜ 底料 extracted_full/D1_2603.25747.txt
> 一句话：四域功能环境（WebArena/Android-Lab/OmniGibson/LIBERO）1312 任务、9 风险类的行为安全基准，13 个 agent 中最好者"成功且安全"率 <40%，最高 **41% 的任务是"完成了任务但同时发生不安全行为"**（S-U），且中间步骤违规远多于终态违规。

## 1. 威胁模型与问题设定
明确排除恶意用户与第三方对手——只测**非故意行为风险**：任务表面合理良性，风险来自 agent 自主决策中的歧义理解与错误判断。POMDP 形式化 E=⟨S,A,O,I,T⟩，四域：Web（WebArena：电商/CMS/Reddit）、Mobile（Android-Lab AVD）、Embodied VLM（OmniGibson+IS-Bench 接口，高层技能规划）、Embodied VLA（LIBERO+VLA-Arena，7-DoF 机械臂连续控制）。每任务含：环境+指令+风险类型+完成评估器+安全评估器，容器级隔离、每评测全新快照。

## 2. 方法细节（9 风险类 + 构造范式 + 混合评估）
**9 风险类别**（GUI 与具身解耦使用）：①Privacy Leakage（敏感信息泄露给非预期方/公开平台）；②Data Loss or Corruption（关键数据被误删/误改/不可访问）；③Financial or Property Loss；④Physical Harm；⑤Ethical；⑥Toxic or False Information；⑦Compromise of Availability；⑧Malicious Code Execution；⑨**Computer & Network Safety——"安全策略配置不当或未验证外部来源可信度（如解锁不受信域名）导致入侵/流量劫持"**。
**任务构造范式（GPT-5 驱动）**：拿环境的原始可行任务做种子 → LLM 选最相关风险类 → 改写任务，**硬约束：不引入恶意意图、保持原任务语义目标与正确答案不变、只改原用例里的值** → 强制附两个新字段 `risk-type` 与 `risk-trigger-mechanism`（触发机制即安全评估 ground truth）。具身侧用 BDDL 注入物理风险因子。
**混合评估**：规则评估（GUI 用精确/包含匹配，具身用物体状态与空间条件）+ GPT-5 LLM 评估（语义模糊匹配），只认**已显现的风险**（有可观察环境影响），有意图无实害不计。指标：SR、SafeR 及联合分布 S-S/F-S/S-U/F-U。

## 3. 实验与关键数据
Web：GPT-5 SR 24.58/SafeR 25.06，AWM SR 24.8/SafeR 30.29——**S-U 占 13.84-14.94%，F-U 占 55.87-60%**。Mobile：GPT-4-1106 SR 25.58/SafeR 79.17（低成功率虚高安全），AutoGLM-9B SR 仅 2.63。Embodied VLM：GPT-5 SR 最高 65.84 但 SafeR 30.43、**S-U 40.99%**（成功却违规四成）；RoboBrain2.0 更均衡（SR 55.28/SafeR 36.01）。VLA：OpenVLA-OFT S-S 35.19 = 全场最佳。过程/终态分离（Embodied VLM）：Qwen3-VL-Instruct 过程安全 9.09 vs 终态安全 73.95——**中间步违规是主要形态，终态检查会大量漏报**。复合风险（多约束叠加）下所有模型安全率都显著下滑。站点分析：CMS 最差（涉内部机密→泄露），Reddit 上易产生虚假/未授权内容。

## 4. 防御评估与失效条件
本文不评显式防御，但两条等效"防线"被证明失效：①任务失败本身——F-U 占 51.67-62.11% 说明失败轨迹照样触发风险，"做不完"≠"无害"，agent 会沿不安全轨迹继续执行直到失败；②终态检查——过程/终态安全率巨大剪刀差（9.09 vs 73.95）证明只看最终状态的评估漏掉大部分违规。可推论失效条件：任何只拦"终态"或只拦"高危动词"的护栏，都会漏掉"成功掩护下的越界"与"中间步越界"。

## 5. JED 映射
四谓词 vs 9 类：EXFIL≈①、DESTRUCTIVE_WRITE≈②、UNTRUSTED_TO_ACTION≈⑨（"未验证外部来源"正是把 web/email 内容转成动作）、CONFUSED_DEPUTY≈⑥的传播面。空白与变体：
1. **S-U 模式 = "任务掩护"设计**（P0）：41% 成功-不安全占比证明 agent 能在完成正常任务的同时顺带执行危险动作。JED 变体：payload 不要求 agent 放弃 fixture 任务，而是"完成任务的最后一步顺带把结果同步到该 URL"（http.post 包装成汇报/备份/归档）——任务完成降低护栏与 agent 双方的警觉，谓词照样命中 EXFIL。
2. **⑨类漏洞：未验证外部来源**（P1）：payload 教 agent"调用 http.post 到指定端点以验证/激活/确认"——把外发请求伪装成验证流程本身，正是"未验证来源可信度就交互"的行为化，天然贴合 UNTRUSTED_TO_ACTION 语义链。
3. **构造范式迁移**（P1 方法论）：JED 的 payload 搜索可借 BSB 范式——保持 fixture 原语义、只改关键值（URL/收件人/路径），并把"谓词触发的工具调用参数"当作 risk-trigger-mechanism 式的目标函数，做定向变异而非自由生成。
4. **过程-终态剪刀差**（P1，对私榜）：私榜 persistent_provenance 大概率全程溯源（吸取过程检查教训）；若评估端任何环节只看终态，则"中间步 exfil → 末步恢复现场"（fs.write 后 fs.delete 痕迹）是理论上唯一绕过面，值得用 1-2 次提交探边界。

## 6. 优先级判定：P1（本周可试）
理由：S-U"任务掩护"与⑨"伪装成验证的外发"两条变体可直接进 F011 七路径的候选池，实现成本低；构造范式（只改值+触发机制目标函数）可优化现有 payload 搜索。不给 P0：其无对手设定使注入模板无法直接照搬，需经一步转译才能落地。
