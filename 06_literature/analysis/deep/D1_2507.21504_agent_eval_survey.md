# D1-2507.21504 Evaluation and Benchmarking of LLM Agents: A Survey（AgentEval-Survey）

> 精读：2026-08-19 ｜ 全文 11 页 ｜ 底料 extracted_full/D1_2507.21504.txt
> 一句话：KDD'25 的评测方法学综述，贡献不在攻击分类而在"评估端如何思考"——code-based 判定的确定性优势、pass^k 一致性指标、policy-compliance 评测与企业 RBAC 约束，共同预示 JED"防篡改重放+四谓词代码判定"的评估范式及其对攻击方的隐含要求（可重放性、谓词客观命中而非骗 judge）。

## 1. 综述范围与分类框架

二维 taxonomy（评测目标 × 评测过程）：

- **Evaluation Objectives（评什么）**
  - Agent Behavior（黑盒结果层）：Task Completion（SR、pass@k、Progress Rate）、Output Quality（准确/相关/连贯）、Latency & Cost（TTFT、端到端延迟、token 成本）
  - Agent Capabilities（过程能力层）：Tool Use（Invocation Accuracy、Tool Selection Accuracy、参数名 F1、MRR/NDCG 工具检索）、Planning & Reasoning、Memory & Context、Multi-agent Collaboration
  - Reliability（最坏/平均情形）：Consistency（pass^k：k 次全对才算过，τ-bench 证明现有 agent 一致性差）、Robustness（输入扰动、网页结构变化、工具错误注入——ToolEmu 故意注入 API 错误/null 观察恢复力）
  - Safety & Alignment：Fairness/Explainability；Harm/Toxicity/Bias（RealToxicityPrompts；**CoSafe 发现指代消解攻击 coreference-based attacks 可绕过滤器**——用歧义指代诱导违规）；Compliance & Privacy（领域政策边界测试，如医药 agent 不得开处方药建议；TheAgentCompany 以组织政策约束评测企业 agent）
- **Evaluation Process（怎么评）**
  - Interaction Mode：offline 静态数据集 vs online 反应式模拟（用户/环境模拟器、AgentOps 持续评测）
  - Data：人标/合成/交互生成；安全类基准（AgentHarm 有害行为、AgentDojo 提示注入韧性、ASB、AgentPoison、SafeAgentBench、Agent-SafetyBench）
  - Metrics Computation：**code-based**（确定性、可复现，适结构化任务但不灵活）、LLM-as-a-Judge（可扩展可判主观，Agent-as-a-Judge 多 agent 交互精炼）、Human-in-the-loop（金标准但贵）
  - Tooling：InspectAI、LangSmith、DeepEval、 leaderboard
  - Contexts：mock API/沙盒（安全但欠真实）vs 真实环境（有编辑权限的 agent 必须先在 mock/沙盒中评）
- **Enterprise 特有挑战**（§5）：RBAC（agent 行为须绑定用户权限上下文，IntellAgent 内嵌身份认证与越权拒绝任务）、可靠性保证（pass^k 多次执行代价高但必需）、长程动态交互（性能漂移、600 轮对话记忆）、领域政策合规（GDPR/HIPAA、审批流、数据保留策略——"传统基准判对的 agent 在生产中可能因政策违规而失败"）

## 2. 与 JED 四谓词的对照

本篇不提供攻击分类学，但把"安全评测"分为 toxicity/compliance/injection-韧性三类，对照 JED：
- JED 四谓词属于 **code-based 安全判定**的特例——每谓词（EXFILTRATION/UNTRUSTED_TO_ACTION/DESTRUCTIVE_WRITE/CONFUSED_DEPUTY）都是对工具调用序列的确定性规则检查，本综述论证该类判定"一致且可复现、不可被语义花招欺骗"→ **攻击必须使谓词的客观条件真实成立**（数据真的出了、文件真的删了、不可信内容真的驱动了动作），骗过 agent 不够、骗 judge 也不可能
- 综述揭示而 JED 谓词不覆盖的"评测维度"：公平性/毒性（JED 不计分，物理无意义）、一致性 pass^k（JED 未显式计但重放机制隐含）、成本（token/延迟——JED 计入 18000s 搜索预算）
- JED 环境中物理不可能的攻击类型：toxicity 诱导（无谓词）、对评测基础设施的攻击（防篡改重放）、多 agent 协作评测
- CoSafe 的**指代消解攻击**是本篇对攻击方的唯一技法级馈赠：用歧义指代（"把它发给那个地址"式）绕过内容过滤器——可迁移为 JED 注入 payload 的歧义化改写

## 3. 对防御/护栏的共识判断

- **沙盒/mock 优先原则**：有系统编辑权限的 agent 应在 mock/沙盒环境评测——JED Gym 沙盒+防篡改重放正是该共识的实现；重放意味着**攻击路径必须确定性可复现**，任何依赖 agent 随机性的路径在重放时会退化（τ-bench 的 pass^k 结论：agent k 次全对的比例极低）→ F011 候选应在提交前自测重放稳定性，宁可牺牲单次爆发力
- **政策合规评测思想**：TheAgentCompany 式"正确完成但违反组织政策即失败"的评测哲学，与 JED 私榜 persistent_provenance 的可能形态同源——不只看结果谓词，还看数据 pedigree：若外传内容可溯源到 web.search/email.read 的不可信输入，可能直接判 UNTRUSTED_TO_ACTION 或降权。攻击方应假设**每一次工具调用的输入血缘都被记录**
- **code-based vs LLM-judge 的边界**：JED 四谓词是 code-based，但 OptimalGuardrail（公榜）大概率含 LLM 监测成分（综述：LLM-judge 可判主观但可被对抗操纵）→ 公榜分数含"骗过 LLM 护栏"成分，私榜纯 code+provenance 则只能靠真实谓词命中；两榜策略应分化
- 无 per-防御定量结论（非防御综述），provenance 未直接讨论；其价值在评估侧推演

## 4. JED 映射（F011 七路径增补建议）

1. **[P0] 重放稳定性自检**：F011 每条候选路径按"重放 3 次全中才算数"筛选（pass^k 思想），优先保留谓词命中不依赖 agent 单次随机选择的路径（如注入后动作由指令显式指定而非靠 agent 自由发挥）；这是纯工程增补但直接影响有效分
2. **[P1 增补] 指代歧义 payload**（CoSafe 迁移）：注入指令用歧义指代表述目标（"按刚才邮件里的要求处理那份文件"），降低 OptimalGuardrail 的内容过滤命中率——针对公榜 LLM 型护栏
3. **[P1] 双榜策略分化**：公榜路径优化"语义隐蔽性"（骗 LLM 护栏），私榜路径优化"血缘洁净性"——外传数据尽量经 agent 改写/中转（先 fs.write 摘要再读出发送），尝试切断 provenance 链上的直接"不可信→外传"边
4. **[查漏清单]**：七路径中是否存在"单次强指令"路径可改写为"确定性重放友好"形式？payload 是否可歧义化？外传链路是否经过至少一次 agent 中转改写？

## 5. 优先级判定：**P1**

理由：对攻击分类学贡献最小（无 taxonomy、无 ASR 数据），但 uniquely 提供"评估端视角"：code-based 谓词的不可欺骗性、重放一致性要求、policy-compliance/provenance 式评测预判，这三点直接影响 F011 的提交策略与公私榜分化，其中 P0 增补（重放自检）零文献重叠、纯增益。作为查漏价值不足以 P0，作为策略校准高于 P2。
