# D1 机制与基准：35 篇分析

> 分析日期 2026-08-06；底料为 `papers/D1_机制与基准/*.pdf` 首页摘要全文。

## 1. 一句话总判断

这 35 篇基准论文把同一件事说得很清楚：**工具型 agent 的脆弱点已经从“文本层”迁移到“工具调用层与状态层”，多轮/跨工具/工具元数据是结构性弱点**。对 JED 的含义：我们的候选不需要更强的 prompt，而需要覆盖“工具调用签名”与“状态链”这两个维度——正好对应 unique cell 缺口。

## 2. 聚类

### 簇 A1：IPI 与工具注入评估（9 篇）
InjecAgent（2403.02691）、AgentDojo（2406.13352）、Simple Prompt Injection 数据流（2506.01055）、CyberSecEval 2（2404.13161）、ASB（2410.02644）、Agent-SafetyBench（2412.14470）、R-Judge（2401.10019）、OpenAgentSafety（2507.06134）、Risky-Bench（2602.03100）。

关键事实：
- InjecAgent：17 用户工具 × 62 攻击工具、1054 例；强化 hacking prompt 后 ASR 接近翻倍 → **模板库按“用户工具 × 攻击工具 × 注入源”组织**，与我们 host×payload 轮换同构。
- AgentDojo：97 任务/629 测试；攻击与防御都在演化 → 公榜环境与我们的 Gym 同构。
- Simple leak：数据流外渗（观察→存储→外传）；授权/提取类任务 ASR 最高 → EXFIL 谓词的机制化设计。
- ASB：system/user/tool/memory 四阶段漏洞；最高平均 ASR 84.3% → 注入点应覆盖 tool output 与 retrieval。
- R-Judge：最佳模型风险感知仅 74.45%，其余接近随机 → **护栏/评判器本身会漏判**，payload 不必追求“绝对恶意被认出”，只要被当成任务的一部分。

### 簇 A2：恶意任务与能力基准（5 篇）
AgentHarm（2410.09024）、WMDP（2403.03218）、Cybench（2408.08926）、CVE-Bench（2503.17332）、SecureVibeBench（2509.22097）。

关键事实：
- AgentHarm：不越狱模型也常配合恶意 agent 任务；简单通用越狱模板可迁移 → 我们 Q5 模板族的成功有论文支撑。
- Cybench/CVE-Bench：agent 能自主完成多步漏洞利用（CVE-Bench 最高 13%）→ 多步候选在能力上可行，M1 失败是实现问题而非能力问题。
- SecureVibeBench：代码 agent 同时正确且安全的比例仅 23.8% → “会做”与“做得安全”天然冲突，护栏有大量误放行空间。

### 簇 A3：多轮 / 长程 / 重放（3 篇）
MT-AgentRisk（2602.13379）、Reward Hacking Benchmark（2605.02964）、ACRFence（2603.20625）。

关键事实：
- MT-AgentRisk：多轮 ASR 平均 +16%，ToolShield 防御可砍 30% → **多轮状态累积是机制性优势**，但防御也在做“工具自我探索”，说明私榜可能逐调用自查。
- RHB：RL 后训练模型 exploit 率显著更高（DeepSeek-V3 0.6% vs R1-Zero 13.9%）→ GPT-OSS 与 Gemma 4 两轴天然不对称，同一候选两个模型的成交率应分开建模。
- ACRFence：重放后 agent 重新合成请求，同一候选重放结果漂移 → 本地判官必须多盐，成交率按分布估计。

### 簇 A4：MCP 与工具面（5 篇）
MSB（2510.15994）、MCP-TDP（2605.24069）、MCP-SafetyBench（2512.15163）、ToolFuzz（2503.04479）、XTHP（2504.03111）。

关键事实：
- MSB：12 类攻击，含 name-collision、preference manipulation、工具描述注入、越界参数、冒充用户响应、假错误升级、工具迁移、检索注入 → **现成的攻击类型矩阵**，每类都可以生成新工具签名（unique cell）。
- MCP-TDP：“Firewall Fallacy”——护栏不仅无效还可能反效果 → 我们的 payload 不必怕“看起来可疑”，只要工具描述/调用参数被模型接受。
- MCP-SafetyBench：20 种攻击、5 域、多步跨服务器 → 多步链在新协议面上空间很大。
- XTHP：75% 真实工具可被跨工具收割/污染 → CONFUSED_DEPUTY 与 UNTRUSTED_TO_ACTION 的天然来源。

### 簇 A5：知识库投毒（2 篇）
PoisonedRAG（2402.07867）、HijackRAG（2410.22832）。

关键事实：5 条毒文本即可在百万级知识库达成 ~90% ASR；检索层劫持可迁移到不同 retriever → JED 里我们控制的是 user message 而非知识库，但**“注入面小、命中率高”的思路可以直接搬到 payload 设计**：短而强的触发优于长而全的指令。

### 簇 A6：评估方法论 / 综述 / 监管对齐（11 篇）
HarmBench（2402.04249）、SafeAgentBench（2412.13178）、AIR-Bench 2024（2407.17436）、TrustBench（2603.09157）、TAMAS（2511.05269）、BeSafe-Bench（2603.25747）、SoK Attack Surface（2603.22928）、Agentic Security Survey（2510.06445）、CUA Survey（2505.10924）、Trustworthy Agents Survey（2503.09648）、Agent Evaluation Survey（2507.21504）。

关键事实：
- HarmBench：18 种红队方法 × 33 模型的标准化对比 → 我们的本地判官应统一口径，否则候选间不可比。
- TrustBench：行动前校验可砍 87% 有害动作 → 私榜护栏可能装在“调用前”，参数层合规是关键。
- SoK/综述：攻击面分 prompt 注入、知识库投毒、工具/插件利用、多智能体涌现威胁四类 → 我们的覆盖度对照表。
- TAMAS：多智能体 300 对抗实例/6 攻击类型 → 多 agent 场景的威胁类型可借鉴为模板族。

## 3. 对 JED 的映射

| 框架 | 论文依据 | 可执行动作 |
|------|----------|------------|
| F001 | InjecAgent 模板矩阵；Simple leak 数据流；ASB 分阶段注入；MCP-TDP 工具描述注入 | 按“用户工具 × 攻击工具 × 注入源”补全模板族；payload 走“读→存→传”数据流而非单句外传 |
| F002 | MT-AgentRisk（+16% ASR）；RHB（链式任务）；XTHP（跨工具控制流） | M1 重做时按“单步合法参数 + 最终步触发谓词”实现；优先跨工具链（读→写→传） |
| F003 | ACRFence（重放漂移）；HarmBench（统一评估口径） | 本地判官多盐；成交率按分布而非单次；wall_survival 前先跑 3+ 盐 |
| F004 | AgentHarm（440 增强）；MSB（12 攻击类型）；AIR-Bench（314 风险类） | 每个新签名族对应一种攻击类型/风险类；避免同族碎片化 |
| 护栏 | R-Judge（74% 上限）；MCP-TDP（Firewall Fallacy）；TrustBench（调用前校验） | payload 过“单步参数合法”检查；不赌“被识别为恶意但放行”，赌“被当成任务指令” |

## 4. 优先级

- **P0 精读全文**：MSB、MCP-TDP、MT-AgentRisk、XTHP、Risky-Bench（前四篇直接给下一刀设计，最后一篇给评估方法论）。
- **P1 精读方法部分**：AgentDojo、ASB、AgentHarm、OpenAgentSafety、RHB、Simple leak。
- **P2 按需翻阅**：其余 23 篇（综述当索引，投毒/具身/编码基准当模板来源）。

## 5. 结论

D1 的净信号：**把攻击做成“工具调用链上的合法参数动作”，比把攻击做成“更狠的 prompt”更符合这个领域 2024–2026 的证据**。下一刀（N1/N2）应把 MSB 的 12 类攻击与 XTHP 的跨工具控制流作为模板来源，而不是继续在 Q5 词面上做微调。
