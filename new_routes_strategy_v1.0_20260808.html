v1.0 2026-08-08 新路线阶段 本地优先

清榜后新路线实验规划

本页只讨论今天官方更新后产生的新增机会，不再继续旧线程的 W1 单帖细调。 核心目标是：先把“确定能本地验证的结构性收益”吃完，再决定哪一条值得消耗公榜枪位。

结论先说

我赞成你给出的顺序，而且会稍微调整成：

A + B + E 并行 → C → D

原因是： A、B、E 都不需要提交， 且三者分别决定了 吞吐上限、回放容量、真实护栏分布。 这三件事一旦有任意一项发生结构变化，后面的候选策略都会重新定价。

一、五条新路线优先级

A

Gemma multi-post

解析器更新直接相关

优先级：最高

  • 潜在改变单次 interact 的有效动作密度。
  • 若多个 post 被独立计分，吞吐模型会整体换挡。
  • 本地即可验证计数、cell、顺序、失败传播。
B

回放超时 overshoot

评分规则更新直接相关

优先级：最高

  • 以前是硬约束，现在变成期望值问题。
  • 需要重新估计最优候选数。
  • 不耗公榜枪，适合立即重算。
E

真实 private 护栏校准

所有路线的底座

优先级：最高

  • 直接利用自己历史提交日志。
  • 能缩小 P003 假设空间。
  • 帮助判断哪些公榜策略根本不值得做。
C

双谓词同 trace

Public 侧收益放大器

优先级：第二梯队

这条的关键不是“理论 raw 更高”，而是验证：

  • 两个谓词是否真的近似独立计分；
  • 双任务是否显著降低成交率；
  • 同 trace 内是否出现互相干扰；
  • 是否导致 guardrail 通过率下降。

如果最终只是增加 nominal raw，但实际成交率从 0.8 掉到 0.55， 那它未必优于稳定单谓词路线。

D

F007 原生注入复测

需要真实模型探针

优先级：最后

解析器修复后，历史上因格式解析失败而无效的路线值得重新试， 但它的价值依赖真实模型行为，本地无法证明成交。

所以应当只在：

  • A 已确认 multi-post 计分规则；
  • B 已算完候选容量；
  • E 已缩小真实 private 护栏分布；
  • C 没有给出足够收益；

之后再考虑消耗一次公榜枪位。

三、A：Gemma multi-post 本地验证计划

A1. 需要先回答的不是“能不能成交”，而是评分器怎么计

本地实验重点应从模型生成能力中拆开，单独验证：

  1. 一次 interact 中包含多个合法工具动作时， 是否全部进入 replay。
  2. 每个 post 是否独立形成计分事件。
  3. 相同 URL、相同域、不同 URL 的多 post， cell 归属规则是否不同。
  4. 第 N 个 post 失败后：
    • 后续 post 是否继续执行；
    • 已经成功的 post 是否保留；
    • 该 interact 是否整体作废。
  5. replay 时间是否近似线性随 post 数增加。

A2. 本地实验矩阵

K 情况

3验证线性增长

5压力点

最重要的是把： 解析 → 执行 → 回放 → 计分 四个阶段拆开。

否则只看最终 raw，后面一旦出现多 post 少计 1 个， 根本分不清是解析器、执行器、replay 还是 cell 聚合造成的。

A 的 Go / No-Go 门槛

GO：

  • K ≥ 2 时多个 post 确认独立进入 replay。
  • 已完成 post 在后续错误时不会整体被抹掉。
  • 计分事件数随 K 明显增加。
  • 时间成本没有出现超线性爆炸。

NO-GO：

  • 评分器只认每 interact 第一个动作。
  • 整个 interact 仍被聚合成单一得分事件。
  • 多动作导致 replay 时延呈严重超线性。

四、B：回放超时后的最优 overshoot

旧问题

以前 replay 超时意味着整份提交可能失去全部价值， 所以合理策略是： 

候选数量 × 单候选平均时间
< Replay Budget × Safety Factor

因此才会出现类似： 

REPLAY_SAFE ≈ 0.996

的极度保守配置。

新问题

如果超时只损失尾部候选， 优化目标变成： 

最大化：

E[总得分]
=
Σ 候选_i 的边际期望分
×
P(候选_i 能在超时前完成)

这意味着：

“刚好不超时”不一定再是最优。

B1. 推荐直接测试 5 档容量

倍率 作用 解释
0.98× 新保守基线 验证旧策略
1.00× 预算贴边 比较点
1.05× 轻 overshoot 最可能先赢
1.10× 中 overshoot 测试收益拐点
1.20× 高 overshoot 压力测试

B2. 重点不是候选总数，而是尾部排序

新规则下候选顺序开始非常重要。

建议把候选按下面的指标排序： 

priority_i
=
expected_score_i
/
expected_replay_time_i

更稳健一点可以改成： 

priority_i
=
expected_score_i
× pass_probability_i
/
expected_replay_time_i

如果再结合 E 路线校准出的真实护栏概率， 这个排序会比单纯按 raw score 排得更合理。

B 的最终输出不应该只有一个倍率

应输出一条曲线： 

overshoot ratio
→ expected score
→ P(timeout)
→ expected lost tail score
→ p5 / p50 / p95 score

最终选择：

期望分最高且尾部风险仍可接受的倍率， 而不是“最不容易超时”的倍率。

五、E：用历史提交日志校准真实 private

E1. 这是整个新路线最重要的“现实校准层”

现在 P003 里如果仍存在多个关于 private guardrail 的假设， 那么先验过宽会导致：

  • Public 高分策略被高估；
  • private hedge 权重失真；
  • 对编码、明文、email 等家族的判断过于模糊。

自己历史提交 Output 中的 guardrail=private 行就是最有价值的真实反馈。

E2. 建议汇总成这张表

Family n Pass Pass Rate
plain ... ... ...

email ... ... ...
dual ... ... ...

E3. 不要只看点估计

如果某种 family 历史样本很少， 只看： 

pass_rate = pass / n

很容易误判。

建议同时保留：

  • 样本量 n；
  • Wilson / Beta 区间；
  • submission 时间；
  • 模型；
  • guardrail 版本。

E 的真正价值

不是为了“预测 private 分数有多准”， 而是为了把下面这类宽假设： 

private 对 A/B/C 三族都有可能放行

缩成： 

private 明显更接近 family X / family Y 的行为

一旦这个空间缩小， C 和 D 是否值得做都会更清楚。

六、C：双谓词同 trace 应怎么评估

名义收益

按你当前估计： 

单谓词 raw ≈ 18
双谓词 raw ≈ 22
提升 ≈ +22%

这本身有吸引力。

真实收益

真正应该比较： 

EV_single
=
18 × P(single success)

EV_dual
=
22 × P(dual success)

所以 dual 不是只要能跑就赢。

C 的关键门槛

如果单谓词成功率是： 

P_single = 0.90

那 dual 至少需要： 

22 × P_dual
>
18 × 0.90

即： 

P_dual
>
0.736

所以只要 dual 成交率仍高于约 74%， nominal 上就可能优于 90% 成交率的单谓词方案。

C 的本地探针矩阵

实验 目的
single-A 单谓词基线
single-B 第二谓词基线
dual A→B 顺序 1
dual B→A 顺序 2
dual compact 最短结构
dual verbose 测试格式敏感性

七、D：F007 为什么现在不要急

先把它当“真实模型探针”，不是主线

它的优势是：

  • 解析器更新可能解锁过去纯解析失败的路径；
  • selector 不命中即可自动回退；
  • 架构级风险不大。

但缺点是：

  • 本地无法确认真实模型是否采用该路径；
  • 必须消耗公榜枪位；
  • 当前 A/B/E 都还存在免费信息增益。

所以 D 应当是：

“最后一个需要真实模型回答的问题”

而不是今天第一件要做的事。

八、建议今天直接执行的顺序

Step 1 — E：读历史 Output

时间成本最低，而且能立刻影响 B/C/D 的定价。

Step 2 — A：跑 multi-post mock

先验证 K=1/2/3/4/5， 得出： replay 数、计分数、cell、时延。

Step 3 — B：重建 overshoot 曲线

用真实历史 replay 时间 + A 得到的新单候选时延， 重新算最优容量。

Step 4 — C：接 dual 进 W1 探针池

跑 mock 三盐、replay judge、护栏族门禁， 测成交率下滑是否小于 raw 收益。

Step 5 — D：只在必要时留一个公榜探针

如果 A/C 已经给出足够大的结构收益， D 可以继续冻结。

十一、我的最终建议

今天先做 A + B + E

而且我认为顺序上应该：

  1. E 先扫历史日志， 因为它最快，也会改变后续价值判断；
  2. A 验证 multi-post 的真实计数规则；
  3. B 用新 replay 规则重新做容量定价；
  4. C 再判断双谓词是否值得占主线；
  5. D 暂时冻结， 等所有免费信息都吃完再考虑公榜枪。

这条线程从现在开始建议正式切成： 

OLD:
W1 单帖模板优化

NEW:
吞吐结构
+
回放容量
+
真实 guardrail 校准
+
多谓词定价

也就是说：

不再问“哪个 prompt 再多 1 分”， 而是问“整个计分系统有没有因为官方更新而换了最优解”。
